# `/ecc-ai-regression-testing`

AI 辅助开发中的回归测试策略：无数据库的隔离 API 检查、自动缺陷检测，以及避免同一模型同时编写和验证更改所产生的盲区。

## 提示词示例

### 1. 简短请求
```text
/ecc-ai-regression-testing 为这项 AI 生成的更改提出回归检查：[描述]。指出作者模型可能忽略的问题。
```

### 2. 模板请求
```text
/ecc-ai-regression-testing 为 [项目/技术栈] 中的更改 [功能/API] 制定回归测试覆盖计划。条件：[是否可访问数据库/外部服务]。列出场景、预期结果和隔离验证方法；另行加入用于发现模型盲区的独立检查。
```

### 3. 详细请求
```text
/ecc-ai-regression-testing 为技术栈[技术栈]中的更改[路径/描述]制定可验证的回归计划。1) 根据现有需求和代码推导更改前后的行为。2) 制定正向、负向和边界场景，包括 AI 实现可能出现的错误。3) 对 API（如适用）提出不依赖数据库的 sandbox 检查。4) 不要修改文件或安装依赖。结果为“场景 — 输入 — 预期结果 — 隔离级别”表格，然后列出覆盖缺口和优先级。
```
