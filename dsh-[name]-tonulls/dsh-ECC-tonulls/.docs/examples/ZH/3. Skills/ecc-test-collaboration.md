# `/ecc-test-collaboration`

清点测试资产，并将需求、业务规则、风险、缺陷及跨服务契约映射到稳定的 TEST-ID 和项目中可执行的证据。

## 简单请求
```text
/ecc-test-collaboration 对需求[列表]进行只读测试缺口分析。不要修改文件。
```
## 模板请求
```text
/ecc-test-collaboration
范围和需求：[描述]
现有注册表/TESTS.md：[路径或内容]
风险/缺陷：[列表]
将需求与现有测试对照并分类缺口；不要创建或编辑文件。
```
## 详细请求
```text
/ecc-test-collaboration
严格以只读方式审计[范围]内的测试资产。在可用背景中查找需求、业务规则、已知缺陷和消费者/提供方边界；将其映射到稳定 TEST-ID 和现有可执行测试/注册表；分类 unit、integration、contract、E2E 和 smoke；评估每个测试的必要性及缺乏证据的领域。不要修改文件或运行测试；未经我确认，不要添加 TEST-ID。报告：可追溯性地图、按风险划分的缺口、重复/过期检查、建议操作及证据限制。
```
