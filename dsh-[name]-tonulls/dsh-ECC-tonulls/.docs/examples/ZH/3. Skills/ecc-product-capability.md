# `/ecc-product-capability`

**用途：**将 PRD 意图、路线图请求和产品讨论转化为可直接实施的 capability 计划：在跨服务工作开始前，记录限制、不变量、接口和未决问题。适用于在 ECC 中将 PRD 结构化转换为 SRS，而不是形成含糊计划。

## 简短提示词

```text
/ecc-product-capability 将[PRD/想法]转换为包含接口、不变量和未决决策的 capability 计划。
```

## 模板提示词

```text
/ecc-product-capability
背景：[PRD/路线图/讨论、目标用户、受影响系统和限制]。
任务：为 [目标组件/结果] 将产品意图转化为可实施的 capability 计划。
重点：用户、限制、不变量、服务间接口，以及需要产品负责人决策的事项。
限制：在回复中准备分析文档；未经同意，不要创建文件或开始实施。
格式：[简要结论、证据/理由、风险和下一步]。
```

## 详细提示词

```text
/ecc-product-capability
为 [目标系统/场景] 执行任务“将产品意图转化为可实施的 capability 计划”。
1. 明确目标、范围、初始信息和结果标准；列出缺失背景。
2. 仅研究与请求相关的材料并核查：用户、限制、不变量、服务间接口和需要产品负责人决策的事项。
3. 制定目标 capability/spec，包含不变量、接口、验收标准和未决决策；区分事实与假设。
4. 根据给定标准检查结论，注明证据、假设和未核实事项。

限制：在回复中准备分析文档；未经同意，不要创建文件或开始实施。
按以下格式整理结果：[预期格式]。不要编造事实；如需执行未预期的副作用操作，请暂停并征求同意。
```
