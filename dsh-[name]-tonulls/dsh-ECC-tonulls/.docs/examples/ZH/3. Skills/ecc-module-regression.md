# `/ecc-module-regression`

**用途：**通过 `REGRESSION.md` 管理大型仓库模块间的回归风险，文档中列明各模块的使用方和可执行验收命令。更改后检查修改的模块及所有受影响命令；按照项目规范，退出代码作为证据。适用于分析回归、依赖关系，以及可能因 A 更改而破坏 B 的情况。

## 简短提示词

```text
/ecc-module-regression 评估此更改可能导致哪些模块和命令出现回归；构建依赖链。
```

## 模板提示词

```text
/ecc-module-regression
背景：[项目路径 / 片段 / 系统 / 症状]。
任务：评估更改对 [目标或对象] 造成跨模块回归的风险。
重点：模块消费者、依赖关系、契约路径和相关验收命令。
限制：只读；不要修改文件，也不要运行主动或外部检查。
结果格式：[简要结论、依据、优先级和后续步骤]。
```

## 详细提示词

```text
/ecc-module-regression
为 [项目/组件/场景] 执行任务“评估更改后的跨模块回归风险”。
1. 记录初始信息、工作范围和结果标准；列出缺少的信息。
2. 仅研究与任务相关的背景并检查：模块消费者、依赖关系、契约路径和相关验收命令。
3. 提出结论和后续步骤；不要应用更改，也不要把假设说成事实。
4. 根据标准核对结果，提供证据并区分已确认的结论和假设。

限制：只读；不要修改文件，也不要运行主动或外部检查。
报告应注明结论、重要发现/操作、未检查部分、风险和安全的后续步骤。
```
