# `/ecc-product-lens`

**用途：**在开发开始前，通过四种分析检验产品依据：YC 风格诊断并生成最终 `PRODUCT-BRIEF.md`，附带是否继续建议；创始人视角的产品市场匹配信号分析；用户旅程和价值实现时间分析；以及 ICE 优先级排序。适用于验证产品方向、选择功能、评估是否发布，或将想法转化为简报。

## 简短提示词

```text
/ecc-product-lens 检查想法[描述]：适合哪些人、多久能体现价值，以及 go/no-go 的标准是什么？
```

## 模板提示词

```text
/ecc-product-lens
背景：[想法/产品、目标用户、当前用户旅程和可用信号]。
任务：为 [目标组件/结果] 在开发前验证产品依据。
重点：问题和细分群体、product-market fit 迹象、用户旅程/价值实现时间、ICE 优先级及 go/no-go 标准。
限制：在回复中准备分析文档；未经同意，不要创建文件或开始实施。
格式：[简要结论、证据/理由、风险和下一步]。
```

## 详细提示词

```text
/ecc-product-lens
为 [目标系统/场景] 执行任务“在开发开始前验证产品依据”。
1. 明确目标、范围、初始信息和结果标准；列出缺失背景。
2. 仅研究与请求相关的材料并核查：问题和细分群体、product-market fit 迹象、用户旅程/价值实现时间、ICE 优先级及 go/no-go 标准。
3. 制定目标 capability/spec，包含不变量、接口、验收标准和未决决策；区分事实与假设。
4. 根据给定标准检查结论，注明证据、假设和未核实事项。

限制：在回复中准备分析文档；未经同意，不要创建文件或开始实施。
按以下格式整理结果：[预期格式]。不要编造事实；如需执行未预期的副作用操作，请暂停并征求同意。
```
