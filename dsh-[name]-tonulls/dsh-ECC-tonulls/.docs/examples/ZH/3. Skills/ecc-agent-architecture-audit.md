# `/ecc-agent-architecture-audit`

**用途：**全面诊断 Agent 和 LLM 应用：审计 12 层技术栈中的封装回归、记忆污染、工具使用错误、隐式修复循环和显示故障。按严重程度报告发现并对代码修复排序。适用于 Agent 应用、自治循环和 LLM 功能的开发者；当 Agent/LLM 故障来源不明或发布技术栈前使用。

## 简短提示词

```text
/ecc-agent-architecture-audit 诊断 [Agent/LLM 功能] 行为异常的原因；找出可能的故障层并用事实验证。
```

## 模板提示词

```text
/ecc-agent-architecture-audit
背景：[项目路径 / 片段 / 系统 / 症状]。
任务：找出 [目标或对象] 的 Agent 或 LLM 应用发生故障的层。
重点：12 层技术栈、封装回归、记忆污染、工具使用规范、隐式重试/修复循环和显示错误。
限制：只读；不要修改文件，也不要运行主动或外部检查。
结果格式：[简要结论、依据、优先级和后续步骤]。
```

## 详细提示词

```text
/ecc-agent-architecture-audit
为 [项目/组件/场景] 执行任务“找出 Agent 或 LLM 应用发生故障的层”。
1. 记录初始信息、工作范围和结果标准；列出缺少的信息。
2. 仅研究与任务相关的背景并检查：12 层技术栈、封装回归、记忆污染、工具使用规范、隐式重试/修复循环和显示错误。
3. 提出结论和后续步骤；不要应用更改，也不要把假设说成事实。
4. 根据标准核对结果，提供证据并区分已确认的结论和假设。

限制：只读；不要修改文件，也不要运行主动或外部检查。
报告应注明结论、重要发现/操作、未检查部分、风险和安全的后续步骤。
```
