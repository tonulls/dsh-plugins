# `/ecc-ml-adoption-playbook`

**用途：**面向 AI Agent 和工程师，为现有的非 ML 项目引入机器学习提供方法：问题定义、数据就绪度、架构隔离和基线模型集成。适用于添加 ML 功能，从问题定义到第一个模型。

## 简短提示词

```text
/ecc-ml-adoption-playbook 为现有应用提出从[业务目标]到第一个可验证 ML 模型的路径。
```

## 模板提示词

```text
/ecc-ml-adoption-playbook
背景：[项目路径 / 片段 / 系统 / 症状]。
任务：为 [目标或对象] 规划在现有项目中引入 ML 功能。
重点：问题定义、数据质量/可用性、基线模型、架构边界和评估标准。
限制：提供建议，不应用更改、不发送消息，也不进行发布。
结果格式：[简要结论、依据、优先级和后续步骤]。
```

## 详细提示词

```text
/ecc-ml-adoption-playbook
为 [项目/组件/场景] 执行任务“规划在现有项目中引入 ML 功能”。
1. 记录初始信息、工作范围和结果标准；列出缺少的信息。
2. 仅研究与任务相关的背景并检查：问题定义、数据质量/可用性、基线模型、架构边界和评估标准。
3. 提出结论和后续步骤；不要应用更改，也不要把假设说成事实。
4. 根据标准核对结果，提供证据并区分已确认的结论和假设。

限制：提供建议，不应用更改、不发送消息，也不进行发布。
报告应注明结论、重要发现/操作、未检查部分、风险和安全的后续步骤。
```
