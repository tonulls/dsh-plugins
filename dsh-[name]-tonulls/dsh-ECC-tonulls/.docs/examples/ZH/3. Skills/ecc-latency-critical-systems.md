# `ecc-latency-critical-systems`

**命令：** `/ecc-latency-critical-systems`

**用途：**诊断和优化对延迟敏感的系统：实时仪表板、市场数据流、Agent 流程、执行网关、队列和缓存。重点关注 p50/p95/p99、数据新鲜度、队列深度、热路径及可验证的 readback 数据。

## 提示词

### 1. 简短请求

> /ecc-latency-critical-systems 分析此数据流 p95 延迟上升的原因，并建议优化前应检查哪些指标和热区。

### 2. 带占位符的模板

> /ecc-latency-critical-systems 系统：[服务/数据流]，症状：[p95/p99/吞吐量/数据年龄]，时间段和负载：[数据]，SLO：[目标]。分析可用指标和代码热路径，区分观察到的事实与假设。提出安全测量计划和优化方案及正确性验证；未经同意，不要修改代码或运行负载测试。

### 3. 详细分步请求

> /ecc-latency-critical-systems 诊断[系统/数据路径]的延迟。1) 明确延迟定义、测量边界、负载、p50/p95/p99、吞吐量、数据新鲜度和队列深度；检查观察窗口是否可比。2) 从入口到消费者追踪热路径，仅根据现有数据识别可测量的瓶颈（队列、网络、计算、缓存）。3) 每次提出一个可验证假设和实验，包含基线、对照负载、正确性 gate 和停止标准。4) 说明如何通过 readback 确认延迟改善且未丢失/错乱数据。结果为“事实 / 假设 / 测量 / 风险”表格及计划与成功标准。不要进行在线更改、运行负载测试、安装软件、访问网络或部署。
