# `ecc-living-docs-governance`

**命令：** `/ecc-living-docs-governance`

**用途：**防止长期项目中的文档过时：为现有文档定义“章程”“地图”“状态”“历史”等角色，并将活跃 Agent 环境连接到规范信息来源。优先沿用仓库现有结构，而不是新增根目录文件。

## 提示词

### 1. 简短请求

> /ecc-living-docs-governance 分析项目中哪些文档与代码不一致，哪些已成为 Agent 背景信息的规范来源。暂时不要进行更改。

### 2. 带占位符的模板

> /ecc-living-docs-governance 项目[路径/仓库]，文档漂移问题：[示例/范围]，活跃 Agent 环境：[说明/文件]。清点现有文档，仅在确有必要时建议其承担“规则”“地图”“当前状态”“历史”角色。先展示信息来源、缺口和计划；保留当前结构，非必要不创建新的根目录文档。

### 3. 详细分步请求

> /ecc-living-docs-governance 为长期维护的仓库[路径]设计文档治理方案。1) 清点现有说明、地图、计划、状态笔记和历史记录，并将其用途及新旧程度与代码对照。2) 为每类背景确定规范信息源，记录重复和冲突。3) 在现有结构内提出最小化更改；对于 Agent harness，说明如何引导其读取规范文件。4) 仅在有证据时，单独考虑已删除/过时内容及防止其被意外重建的方法。格式：文档地图、附证据的差异清单、角色方案和范围受限的实施计划。不要编造流程事实；未经同意不要编辑内容、修改代码、安装软件或访问网络。
