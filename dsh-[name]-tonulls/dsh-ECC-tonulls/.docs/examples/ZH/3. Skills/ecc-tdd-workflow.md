# `/ecc-tdd-workflow`

通过 TDD 循环推进开发：先编写失败测试，再进行最小更改使其通过，随后重构，并针对目标 unit/integration/E2E 覆盖率进行评估。

## 简单请求
```text
/ecc-tdd-workflow 使用 TDD 修复[缺陷]：先编写能复现问题的测试。
```
## 模板请求
```text
/ecc-tdd-workflow
任务和验收标准：[描述]
代码和现有测试：[路径/片段]
限制：[兼容性/覆盖率]
提出 red-green-refactor 循环和重要边界测试。
```
## 详细请求
```text
/ecc-tdd-workflow
使用 TDD 执行任务[描述]。1) 明确验收标准和现有测试结构。2) 设计一个能在当前行为下失败的最小测试。3) 经我确认后添加测试，并仅运行获准的命令。4) 实现最小修复并重新运行测试。5) 在保持测试通过的前提下重构；评估 unit/integration/E2E 缺口和目标覆盖率。不要安装软件包、访问网络、部署或修改无关文件。如果测试或修复会影响数据/外部系统，请暂停并征求确认。报告：更改、red/green 证据、实际运行的命令和剩余风险。
```
