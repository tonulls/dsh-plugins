# `/ecc-brownfield-retrospective`

将 ECC 工程流程追溯应用于项目的现有部分：研究当前状态、还原决策，并按四个维度（思维方式、开发实践、缺失功能、技术选型）建立差距清单。只有收到单独委托后，才通过 plan–TDD–review 流程开展修复。

## 简短请求

```text
/ecc-brownfield-retrospective 评估遗留支付模块：还原当前架构的成因，并按优先级整理差距清单，暂不修改。
```

## 模板

```text
/ecc-brownfield-retrospective 对项目[仓库]中的[路径/子系统]进行回顾。遗留背景：[已知信息]。先只做审计：按四个维度记录证据和未知事项——工程思维、代码实践、缺失能力、技术选型。未经单独同意，不要开始修复。
```

## 分步请求

```text
/ecc-brownfield-retrospective 回顾[项目部分]在[团队交接/长期开发/ECC 引入]之后的状况。
1. 明确审计范围，研究当前状态、历史/文档和现有决策；不要把对过往的猜测说成已确认事实。
2. 按四个维度整理差距：问题定义/思维质量、实现实践、缺失的产品能力、技术选型的合理性。
3. 对每项列明证据（路径/产物）、影响、严重程度和置信度；指出需要向团队核实的问题。
4. 先展示结论和建议顺序。只有在我明确批准具体范围后才开始修复；届时通过 plan–TDD–review 制定并执行小步骤。
5. 未经单独同意，不要安装依赖、访问网络或部署。

输出：该部分的简要状态、附证据和优先级的差距表、问题和安全行动计划。如果请求的是审计，不要修改代码。
```
