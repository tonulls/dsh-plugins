# `/ecc-change-impact`

在更改代码、数据、接口或治理规则前，基于证据分析影响范围：调用路径、架构、API 契约、测试、文档/ADR、迁移、部署和回滚。实现后，将预测与实际 diff 对照。

## 简短请求

```text
/ecc-change-impact 评估将用户字段重命名为公共 API 字段的 blast radius，并在任何更改前列出安全的操作顺序。
```

## 模板

```text
/ecc-change-impact 分析[模块/文件]中的更改[描述]。风险/背景：[迁移、auth、公共契约等]。实现前追踪依赖和受影响的数据、接口、测试及文档；提出 rollout/rollback 方案。当前只做分析，不要修改代码。
```

## 分步请求

```text
/ecc-change-impact 对[边界]内的更改[准确描述]进行影响分析。重点关注：[数据架构 / auth / 公共接口 / 跨模块依赖]。
1. 研究实际调用路径及读写位置；每项结论都提供可核实的路径/符号，或注明证据缺口。
2. 评估数据和架构兼容性、API/event contracts、消费者、测试及治理文档（README/ADR 等）。
3. 更改前提出操作顺序，必要时包括 expand-contract 或数据迁移、兼容性窗口、可观测性、rollout 和回滚。
4. 如果另行批准实施，则完成后将预测与实际 diff 对照：标记意外受影响的组件和未解决事项。不要执行迁移/部署。

结果：影响图、证据和置信度、按优先级排列的风险、验证/回滚计划。若请求审查，只做分析，不进行修复。未经单独同意，禁止安装软件包、访问网络和部署。
```
