# `/ecc-context-and-decisions`

帮助将稳定的领域术语和背景记录在范围严格受限的 `CONTEXT.md` 中，并与难以撤销、应通过 ADR 记录的架构决策区分开来。

## 简单请求

```text
/ecc-context-and-decisions 团队对“工作区”一词指代不同实体；请提出统一定义的记录方式。
```

## 模板请求

```text
/ecc-context-and-decisions
领域/模块：[名称]
术语或反复出现的背景：[描述]
不同解释及后果：[示例]
当前文档结构：[路径]
请提出一份范围明确的背景文档，或指出这是应记录为 ADR 的架构决策。
```

## 详细请求

```text
/ecc-context-and-decisions
分析[模块/项目]中的领域术语歧义问题。1) 从提供的材料中收集术语和示例。2) 区分稳定的领域定义与结构/技术决策。3) 仅为确实需要重复参考的背景提出最小化的 CONTEXT.md；难以撤销的决策应走现有 ADR 流程。4) 指出对模块边界的影响和待解决问题。未经我确认，不要创建或编辑文件；先展示草稿和建议位置，并考虑现有文档结构。结果包括术语表、分类和更改提案。
```
