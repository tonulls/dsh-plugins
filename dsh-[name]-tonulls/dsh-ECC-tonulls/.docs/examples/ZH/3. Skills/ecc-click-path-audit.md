# `/ecc-click-path-audit`

**用途：**追踪每个按钮或交互点完整的状态变更周期。查找单项功能看似正常，但彼此抵消、产生错误结果或导致 UI 状态不一致的问题。适用于常规调试无法定位按钮问题，或大型共享状态存储重构之后。

## 简短提示词

```text
/ecc-click-path-audit 追踪这些按钮的状态变更路径，找出操作彼此抵消或破坏 UI 的场景。
```

## 模板提示词

```text
/ecc-click-path-audit
背景：[项目路径 / 片段 / 系统 / 症状]。
任务：追踪 [目标或对象] 中每个交互点完整的 UI 状态变更周期。
重点：按钮处理程序、store/state transitions、副作用及界面状态不同步。
限制：只读；不要修改文件，也不要运行主动或外部检查。
结果格式：[简要结论、依据、优先级和后续步骤]。
```

## 详细提示词

```text
/ecc-click-path-audit
为 [项目/组件/场景] 执行任务“追踪每个交互点完整的 UI 状态变更周期”。
1. 记录初始信息、工作范围和结果标准；列出缺少的信息。
2. 仅研究与任务相关的背景并检查：按钮处理程序、store/state transitions、副作用及界面状态不同步。
3. 提出结论和后续步骤；不要应用更改，也不要把假设说成事实。
4. 根据标准核对结果，提供证据并区分已确认的结论和假设。

限制：只读；不要修改文件，也不要运行主动或外部检查。
报告应注明结论、重要发现/操作、未检查部分、风险和安全的后续步骤。
```
