# `/ecc-agent-introspection-debugging`

帮助以可复现的方式诊断 Agent 启动故障：记录观察结果、定位原因、执行有限恢复，并生成自检报告，避免盲目重试。

## 提示词示例

### 1. 简短请求
```text
/ecc-agent-introspection-debugging 根据现有日志分析最近一次 Agent 故障：先记录症状和可能的故障层，不要重试运行。
```

### 2. 模板请求
```text
/ecc-agent-introspection-debugging 研究 [环境] 中启动失败的情况 [标识符/时间]。仅使用可用的[日志、跟踪、输入数据]。只有在[条件/无]下才允许复现。区分已确认事实与假设，并提出不修改文件的有限恢复方案。
```

### 3. 详细请求
```text
/ecc-agent-introspection-debugging 对 Agent 故障[标识符]进行结构化诊断。1) 保存可用的运行事实：任务、操作顺序、工具响应和故障点；不要泄露机密。2) 将症状与可能的故障层进行对照，区分证据与推测。3) 不要自动重试，也不要更改代码或设置。4) 如果验证需要重新执行或产生副作用，请暂停并征求同意。结果包括：简要时间线、可复现条件、附证据的可能原因、安全的下一步和自检报告。
```
