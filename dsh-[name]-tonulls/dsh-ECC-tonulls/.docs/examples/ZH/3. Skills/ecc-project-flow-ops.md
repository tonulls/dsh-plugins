# `/ecc-project-flow-ops`

**用途：**管理 GitHub 和 Linear 工作流：整理 issues 和 pull requests、关联进行中的任务，将 GitHub 保留为公开界面、Linear 作为内部执行工具。适用于管理 backlog、整理 PR 以及协调 GitHub 与 Linear。

## 简短提示词

```text
/ecc-project-flow-ops 为[issues/PR]制定 triage 计划，关联公开的 GitHub 和内部 Linear；不要进行更改。
```

## 模板提示词

```text
/ecc-project-flow-ops
背景：[issue/PR 列表、关联的 Linear 任务、优先级标准和访问限制]。
任务：为 [目标组件/结果] 协调 GitHub 与 Linear 之间的任务和 PR triage。
重点：状态、进行中工作的关联、backlog 优先级、公开/内部边界，以及未经许可不得发布。
限制：制定计划和验证标准；不要修改代码、数据、排期或外部系统。
格式：[简要结论、证据/理由、风险和下一步]。
```

## 详细提示词

```text
/ecc-project-flow-ops
为 [目标系统/场景] 执行任务“协调 GitHub 与 Linear 之间的任务和 PR triage”。
1. 明确目标、范围、初始信息和结果标准；列出缺失背景。
2. 仅研究与请求相关的材料并核查：状态、进行中工作的关联、backlog 优先级、公开/内部边界，以及未经许可不得发布。
3. 根据事实提出发现或备选方案，注明风险、验证标准和未解决问题；不要应用任何更改。
4. 根据给定标准检查结论，注明证据、假设和未核实事项。

限制：制定计划和验证标准；不要修改代码、数据、排期或外部系统。
按以下格式整理结果：[预期格式]。不要编造事实；如需执行未预期的副作用操作，请暂停并征求同意。
```
