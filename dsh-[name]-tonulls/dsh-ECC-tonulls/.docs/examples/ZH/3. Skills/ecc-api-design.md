# `/ecc-api-design`

设计和分析 REST API：资源命名、HTTP 状态码、分页、过滤、错误格式、版本控制和速率限制。

## 提示词示例

### 1. 简短请求
```text
/ecc-api-design 检查 REST 端点[方法和路径]的设计：资源、状态码和错误。只做分析，不修改代码。
```

### 2. 模板请求
```text
/ecc-api-design 为[系统]中的[场景]设计 REST API。客户端：[客户端]；预期规模/限制：[数据]。提出路径、方法、分页和错误处理；明确标注未知需求。
```

### 3. 详细请求
```text
/ecc-api-design 审查[任务]的契约[端点/规格]。1) 根据所给需求确定资源和操作。2) 对每条路由注明方法、路径、输入/输出及适当状态码。3) 在适用情况下检查分页、过滤器、统一错误格式、版本控制和 rate limiting。4) 如果能获取现有客户端契约，请核对兼容性。不要修改代码或臆造需求。结果：路由表、附理由的意见和待澄清问题。
```
