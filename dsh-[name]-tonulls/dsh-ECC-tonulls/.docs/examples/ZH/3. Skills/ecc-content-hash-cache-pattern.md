# `/ecc-content-hash-cache-pattern`

提出基于内容 SHA-256 哈希缓存昂贵文件处理结果的模式，不依赖文件路径，自动失效并分离服务层。

## 简单请求

```text
/ecc-content-hash-cache-pattern 如何缓存文件解析结果，使内容更改时缓存自动失效？
```

## 模板请求

```text
/ecc-content-hash-cache-pattern
技术栈：[语言和存储]
处理任务：[计算开销较大的内容]
规模/频率：[估算]
生命周期及并发要求：[条件]
结合现有代码[片段]，提出 SHA-256 缓存方案和服务层边界。
```

## 详细请求

```text
/ecc-content-hash-cache-pattern
为[技术栈]设计操作[处理任务]的结果缓存。要求：不同路径上的相同内容应复用结果；字节发生变化时应使记录失效；应定义冲突/错误/并行处理时的行为；缓存不得改变业务结果。分步说明键和序列化、计算与存储的分离、清理策略及故障安全行为。提供 API 示例，以及验证复用、内容变化、不同路径和并发请求的测试。先只分析和提案——不要修改文件或安装依赖。报告包括：方案、权衡、测试计划和需要澄清的问题。
```
