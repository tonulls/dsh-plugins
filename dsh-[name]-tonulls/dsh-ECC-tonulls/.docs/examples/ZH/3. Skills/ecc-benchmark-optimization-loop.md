# `/ecc-benchmark-optimization-loop`

帮助通过受限、可测量的循环提升程序速度：先记录基线，再逐一检验假设；每个方案都需通过正确性检查，并为最佳安全方案提供可复现命令。

## 简短请求

```text
/ecc-benchmark-optimization-loop 找出并以可测量方式消除任务队列处理缓慢的主要原因。先记录基线指标；正确性优先于速度。
```

## 模板

```text
/ecc-benchmark-optimization-loop 优化[路径或模块]中的[组件/操作]。症状：[可观察的延迟/吞吐量/成本]。目标：[数值阈值]。限制：[内存、兼容性、时间预算]。每个方案仅验证一个假设，使用相同测量方法并检查正确性；如果结果不稳定或行为发生变化，不要采用该方案。
```

## 分步请求

```text
/ecc-benchmark-optimization-loop 加速[具体场景]。按受限循环执行：
1. 确定输入数据和可复现命令；在不改代码的情况下测量基线（耗时/吞吐量及波动范围）。
2. 找出可能的瓶颈并提出多个独立假设。每次迭代只改变一个因素。
3. 对每个方案采用相同 benchmark 和正确性门槛；如果加速破坏结果、不变量或资源限制[注明]，则拒绝该方案。
4. 在尝试[N]个方案、达到目标[指标]或数据不足时停止。未经同意，不要安装依赖、访问网络或部署更改。

输出：基线和方法；“假设 / 更改 / 指标 / 正确性”表格；选定方案，或说明未找到安全收益；可复现命令和测量限制。仅在明确授权时修改代码；否则只提供计划。
```
