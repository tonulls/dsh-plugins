# `/ecc-command-test-coverage`

**用途：**分析现有覆盖率，找出未覆盖的功能、分支和边界情况，然后在项目明确指定的范围内补充测试。只使用本地可用工具和项目现有约定；禁止安装/下载软件包。

## 提示词示例

### 1. 简短请求

```text
/ecc-command-test-coverage 分析订单验证模块的测试覆盖率，并只为该模块添加缺失测试。不要安装依赖。
```

### 2. 带上下文的请求

```text
/ecc-command-test-coverage
检查项目[路径或仓库]中组件[路径/名称]的覆盖率。找出本地可用的覆盖率命令，比较各文件指标，并优先关注[重要功能、分支或错误]。

仅在[精确范围]添加测试，遵循项目现有位置和风格。目标覆盖率限制：[例如 80% / 仅提高当前指标]。未经单独同意，不要修改生产代码。只使用已安装的工具；不要运行会下载代码的 npx，也不要安装软件包。如果现有工具无法测量覆盖率，请说明限制，不要为此安装工具。
```

### 3. 详细请求

```text
/ecc-command-test-coverage
分析并提高[目录/模块]的测试覆盖率，目标为[阈值或具体提升]。按步骤执行：
1. 根据项目配置确定测试框架和本地可用的覆盖率工具。不要下载工具或软件包；若无合适工具，停止并说明限制。
2. 获取基线指标，按覆盖率由低到高列出低于目标的文件。对每个文件识别未验证的功能、分支、错误处理和边界情况。
3. 按优先级提出测试：主流程、错误、极端值/空数据及剩余分支。仅在[精确获准范围]内添加测试，并遵循现有模板、断言和 mock 方式。不要包含真实机密，也不要向外部服务发送数据。
4. 运行本地可用的测试命令，然后重新测量覆盖率。不要更改原有功能或配置；未经事先同意，不要在测试范围外创建文件。删除/覆盖文件及任何副作用操作均需另行确认。
5. 准备报告：指定更改文件的覆盖率前后对比及总体指标（如可用）、新增场景、已执行检查及结果、剩余缺口和阻碍。

如果测试失败或提升需要更改应用代码，请停止、说明原因并请求确认后续操作。
```
