# `/ecc-command-update-docs`

**用途：**根据项目实际权威来源（如脚本、环境变量模板、路由、架构和公开导出）同步文档。更改仅限明确指定的文档；不运行自动生成器。

## 提示词示例

### 1. 简短请求

```text
/ecc-command-update-docs 根据 package.json 脚本更新文档中的命令表；不要更改其他章节。
```

### 2. 带上下文的请求

```text
/ecc-command-update-docs
将文档[路径]与权威来源[package.json / API 架构 / 路由 / 公开导出]进行核对。仅更新[章节名称]，保留作者说明和现有格式。

不要创建其他文档，也不要运行项目生成器或脚本。如果缺少事实或需要推测，请列出问题，而不要编造内容。对指定章节之外的更改、删除或覆盖其他文件，须先与我确认。
```

### 3. 详细请求

```text
/ecc-command-update-docs
根据当前源码，将文档[路径/章节]与[范围：命令、环境变量、API 路由、导出或基础设施配置]同步。分步处理：
1. 查找并阅读对应的权威来源；不要凭空推断行为、值或流程。
2. 列出源码与文档之间的差异，指出受影响位置和事实依据。
3. 仅修改[精确文件和章节]。保留手写内容，只更新与请求有关的信息。不要创建新文档、运行项目生成器或修改源码/配置。
4. 如果缺少准确所需的数据、保留旧信息更安全，或修复超出范围，请停止并请求澄清/确认。未经我单独明确同意，不要删除、重命名或覆盖文件。
5. 报告更改章节及佐证内容的来源；单独列出未解决差异和缺失信息。如果无需修改，请说明。

不要发布文档，也不要将文档发送到外部系统。
```
