# `/ecc-architect` — 提示词示例

## 用途

规划或审查软件系统架构、比较设计方案并识别系统级风险。这是架构分析，不是实现。

## 1. 简短请求

```text
/ecc-architect 审查通知服务的架构：提出可选方案并指出系统风险。不要修改代码。
```

## 2. 模板请求

```text
/ecc-architect 在 {负载、用户、集成} 背景下，为 {系统或更改} 规划/审查架构。限制：{兼容性、运维、时间}。如果已知，请比较 {方案} 在可靠性、复杂度和影响方面的差异；说明建议依据并列出待解决的问题。只做分析，不要修改文件。
```

## 3. 详细请求

```text
/ecc-architect 分析以下架构变更：{目标和场景}。背景：{当前组件、数据流、负载、外部依赖}。限制：{技术、兼容性、可用性、运维}。

1. 明确系统边界和关键需求；另行标出未知假设。
2. 追踪受影响的数据流和组件交互，识别故障点和依赖关系。
3. 若背景允许，比较至少两种可行方案；说明权衡和选择理由。
4. 给出组件、接口和实施顺序层面的目标方案，不要进入代码实现。
5. 列出系统风险、缓解措施、验证标准以及需要负责人决定的问题。

格式：简要结论、已确认的背景、方案与比较、建议、风险、阶段和待解决问题。不要进行任何更改；未经单独同意，不要安装依赖、使用网络或部署。
```
