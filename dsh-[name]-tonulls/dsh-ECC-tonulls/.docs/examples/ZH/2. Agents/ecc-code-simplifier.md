# `/ecc-code-simplifier` — 提示词示例

## 用途

简化最近修改或明确指定的代码，在保持行为不变的同时提升清晰度、一致性和可维护性。应将范围限制在目标代码片段。

## 1. 简短请求

```text
/ecc-code-simplifier 简化 {文件/代码片段}，但不要改变行为。不要扩大修改范围；说明结果。
```

## 2. 模板请求

```text
/ecc-code-simplifier 根据 {代码目标} 整理 {路径或最近修改的部分}。保留公共契约和行为，避免架构重构。只修改 {允许范围}；完成前列出更改以及可用于证明行为保持不变的依据。禁止安装软件包和访问网络。
```

## 3. 详细请求

```text
/ecc-code-simplifier 为了提升 {清晰度/一致性/可维护性}，简化 {具体文件/已修改片段}。假定外部行为和契约保持不变。限制：{允许的文件、项目风格、兼容性}。

1. 首先确定目标代码的实际边界，并研究其调用方、类型和现有约定。
2. 仅找出明显的清晰度改进或局部重复消除；说明每项为何不会改变行为。
3. 未经必要性确认和单独同意，不要更改公共 API、架构、数据格式、错误处理或相邻模块。
4. 只在允许范围内进行最少的局部修改。如果简化需要改变行为或扩大范围，请暂停、说明方案并征求确认。
5. 不要安装软件包、访问网络或部署。未经许可不要运行测试/检查；不要声称执行了未运行的验证。

回复格式：简述简化内容及理由、保留的契约、已修改文件、证据/检查和剩余风险。如果无法安全简化该部分，请保持不变并说明原因。
```
