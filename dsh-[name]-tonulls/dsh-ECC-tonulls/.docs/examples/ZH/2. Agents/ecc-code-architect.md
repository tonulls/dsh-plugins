# `/ecc-code-architect` — 提示词示例

## 用途

研究现有代码库模式，并制定具体的功能实现计划：文件、接口、数据流和构建顺序。这是供开发者使用的蓝图，不是自行实现。

## 1. 简短请求

```text
/ecc-code-architect 按照项目现有约定，为 {功能} 制定实现计划：包括文件、接口和工作顺序。不要修改代码。
```

## 2. 模板请求

```text
/ecc-code-architect 为 {项目路径} 中的 {功能/更改} 设计实现方案。研究 {相关范围} 中的现有示例。条件：{契约、限制、兼容性}。列出文件、接口和数据流、阶段、相互依赖关系及验证标准。只提供计划，不做任何修改。
```

## 3. 详细请求

```text
/ecc-code-architect 为 {功能和预期场景} 在 {项目} 中准备实现蓝图。背景：{用户、输入/输出、集成}；限制：{兼容性、性能、安全性、更改范围}。

1. 查找并研究类似组件的现有实现和项目约定；通过文件路径和符号支持结论。
2. 追踪受影响的数据流和模块边界。确定所需接口、类型/契约及错误处理，不要臆造缺失的需求。
3. 制作“文件/范围 | 预期职责 | 更改 | 依赖项”表格。不要纳入必要性缺乏依据的文件。
4. 安排实现顺序，明确依赖项和可验证的中间结果；列出检查和边界场景。
5. 单独列出架构风险、假设以及编码前需要确认的决策。

格式：简要概述、代码库依据、文件和接口蓝图、数据流、工作顺序、检查、风险及问题。不要编辑文件或开始实现；未经单独同意，禁止安装依赖、访问网络和部署。
```
