# `/ecc-gan-planner` — 提示词示例

## 用途

将简要想法转化为产品规格：描述功能、冲刺、评估标准和设计方向。

## 简短请求

```text
/ecc-gan-planner 将想法“{想法}”扩展为规格，包含功能、阶段和可验证的验收标准。
```

## 模板请求

```text
/ecc-gan-planner 根据想法 {想法}，为 {产品/受众} 编写规格。包括优先级功能、MVP 范围、阶段/冲刺、评估标准和设计方向。区分已提供的信息与假设和问题。
```

## 详细请求

```text
/ecc-gan-planner 将简要想法 {描述} 转化为面向 {目标受众} 的产品规格，并考虑 {平台、限制、时间}。
1. 描述问题、用户和预期结果；不要添加未知的市场事实。
2. 将功能拆分为 MVP 和后续阶段；注明各项功能的价值和依赖关系。
3. 充分具体地描述用户流程和设计方向，以便实施；不要添加未经证实的视觉要求。
4. 将工作拆解为连续的冲刺/阶段，并给出可衡量的结果。
5. 确定 evaluator 可用于核查结果的评估和验收标准；仅在已提供或有明确依据时指定阈值。

格式：简要概述、受众/目标、范围与非范围、功能、阶段、评估标准、假设和待解决问题。仅做规划：不要修改代码、安装软件包、访问网络或部署。
```
