# `ecc-security-reviewer` — 提示词示例

以下示例用于显式调用安全审查角色。请在 DSH 普通消息中同时发送命令和任务。可根据技术栈和项目范围调整措辞。

## 1. 简单简短

```text
/ecc-security-reviewer 快速检查当前项目中明显的安全问题。不要进行任何更改。对每项发现注明文件、行和潜在风险。
```

## 2. 常规模板

```text
/ecc-security-reviewer 以只读方式审计技术栈为 <语言和框架> 的项目 <项目路径> 的安全性。检查用户输入处理、身份验证和授权、机密存储、文件和外部命令处理，以及依赖项。不要修改文件或安装软件包。对每项已确认的问题，注明严重程度、准确的文件和行、风险场景及修复方法。最后列出尚未核查的内容。
```

## 3. 详细分步

```text
/ecc-security-reviewer 对项目 <项目路径>（技术栈：<语言和框架>）进行分步只读安全审计。

1. 首先简要说明审计范围和主要入口点：路由/API、授权、用户数据处理程序、文件上传和解压、进程启动、机密存储。
2. 追踪从外部输入到敏感操作的数据流；对每项疑点检查调用代码、访问控制、错误处理和相关测试。
3. 仅针对项目实际使用的技术栈检查依赖和可用的本地工具。未经单独许可，不要运行无关命令、安装软件包或访问网络。
4. 不要进行任何更改。仅与搜索模式匹配并不足以证明存在漏洞；除非有已确认的可利用场景，否则不要认定为漏洞。

报告应区分已确认的问题和假设。对每项问题注明严重程度、文件和行、攻击所需条件、影响及建议的修复方法。另行列出已检查的文件/范围、执行的检查和剩余信息缺口。如果重要范围尚未核查，不要宣称审计已完成。
```
