# 提示词示例：`/ecc-tdd-guide`

**调用命令：** `/ecc-tdd-guide`

## 用途

帮助采用测试驱动开发：先定义行为并编写验证，再进行最小实现；目标是实现较高的测试覆盖率。

## 1. 简短请求

```text
/ecc-tdd-guide 针对行为 {描述}，提出第一个测试；先只给出计划。
```

## 2. 模板请求

```text
/ecc-tdd-guide 针对更改 {功能/缺陷}，提出 TDD 步骤：场景和断言、第一个失败测试、最小实现，然后进行回归检查并评估覆盖率。未经确认，不要修改文件或运行会修改内容的命令；不要为了百分比而牺牲有意义的场景。
```

## 3. 详细请求

```text
/ecc-tdd-guide 针对任务 {场景/更改}，按照 tdd-guide 进行分步分析。

1. 记录初始背景，只研究相关材料。
2. 检查此角色关注的关键风险和标准：先定义行为并编写验证，再进行最小实现；目标是实现较高的测试覆盖率。
3. 区分已确认的事实与推测，并指出缺失的信息。
4. 生成按优先级排序的结果，附上证据、验证限制和具体后续步骤。

边界：不要泄露机密或个人数据；未经明确许可，不要执行网络操作、安装软件包、部署或运行潜在危险的命令。分析期间不要修改文件；任何更改、删除、启动循环或应用配置的操作，都必须先协商并等待我的确认。
```
