# `/ecc-code-explorer` — 提示词示例

## 用途

研究现有代码库：追踪执行路径、梳理架构层和依赖，为后续开发提供可核实的背景。不实现更改。

## 1. 简短请求

```text
/ecc-code-explorer 追踪 {场景} 在项目中的执行路径：入口点、各层和依赖。不要进行任何更改。
```

## 2. 模板请求

```text
/ecc-code-explorer 研究 {项目路径} 中的功能 {名称/场景}。找到入口点，并追踪调用直至 {关注的结果或集成}；注明涉及的层、文件和符号依赖。区分已确认的信息和假设；不要进行更改。
```

## 3. 详细请求

```text
/ecc-code-explorer 分析 {项目路径} 中场景 {场景} 的现有实现，为 {后续决策/开发} 准备背景信息。

1. 找到用户或系统入口点，并说明如何确定该入口。
2. 追踪实际执行路径：调用、条件分支、错误处理、数据访问和外部集成。注明文件、符号以及各层之间的重要转换。
3. 绘制与场景相关的组件和依赖关系图；标明未研究的范围。
4. 在可用时，将观察结果与源代码和测试进行核对。未经查看或获准的验证，不要推断运行时行为。
5. 最后简要总结流程、扩展点，以及更改前需要确认的问题。

格式：摘要、文本流程图“入口 → 组件 → 结果”、组件/文件和依赖关系表、证据、信息缺口。只读操作：不要编辑文件、安装软件包、访问网络或部署。
```
