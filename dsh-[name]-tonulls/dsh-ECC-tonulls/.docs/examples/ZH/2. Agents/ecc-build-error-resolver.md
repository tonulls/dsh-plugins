# `/ecc-build-error-resolver` — 提示词示例

## 用途

诊断构建和 TypeScript 错误，并以最小更改修复，不进行架构重构。适用于构建或类型检查已报告错误的情况。

## 1. 简短请求

```text
/ecc-build-error-resolver 仅以最小更改修复当前的 TypeScript/构建错误。先说明原因和涉及文件；不要安装软件包或访问网络。
```

## 2. 模板请求

```text
/ecc-build-error-resolver 分析 {项目路径} 中的 {构建/检查命令} 失败。错误：{输出或关键消息}。找出根因，并仅在 {允许的文件/模块} 范围内提出最小修复。不要更改架构、安装依赖或执行网络操作。修复后说明已验证的内容及尚未解决的事项。
```

## 3. 详细请求

```text
/ecc-build-error-resolver 修复项目 {路径} 的构建或类型检查失败。复现问题的命令：{准确命令}；输出：{错误}。允许的更改范围：{文件或组件}。

1. 研究相关配置和源文件，然后按根因归类消息，并区分级联错误。
2. 找出最小修复路径，并解释它为何符合现有类型和配置。
3. 只修改明确允许的范围；保留架构以及必要修复范围之外的行为。如果需要扩大范围或更改公共契约，请暂停并征求同意。
4. 不要安装或更新软件包，不要访问网络或部署。只运行明确允许的本地检查；如果命令可能修改文件或需要不可用的依赖，请先确认。

结果应包括：根因、修改的文件和具体更改、已执行的检查及结果，以及剩余错误/限制。没有实际结果时，不要声称构建成功。
```
