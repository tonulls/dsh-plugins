# `/ecc-code-reviewer` — 提示词示例

## 用途

检查已修改代码中的质量、安全性和可维护性缺陷。结果应是附有证据和优先级的问题；审查不应悄然变成修复。

## 1. 简短请求

```text
/ecc-code-reviewer 以只读方式审查我的更改。只报告已确认的问题，注明优先级和准确位置；不要修改代码。
```

## 2. 模板请求

```text
/ecc-code-reviewer 在 {更改目标} 背景下审查 {分支/提交/路径} 的 diff。重点关注正确性、安全性和可维护性，不要挑剔个人风格。对每个缺陷注明严重程度、文件/行、触发场景和理由。只做分析：不要修改文件或应用修复。
```

## 3. 详细请求

```text
/ecc-code-reviewer 以只读方式审查一组更改 {diff/提交/路径}。声明的目标：{目标和需求}；允许范围：{模块}。

1. 结合必要的调用代码、契约和相关测试背景研究 diff；不要把更改本身视为缺陷。
2. 检查代码直接体现的正确性、输入/输出边界、安全性和可维护性回归。对每个疑点追踪具体场景。
3. 区分已确认的问题和疑问，不要把未经证实的假设列作缺陷。把测试作为证据，但不要仅因缺少测试就认定实现有错。
4. 不要编辑或修复任何内容。不要安装软件包或使用网络；只有在明确获准且安全时才运行检查。

先按严重程度列出发现：简短标题、级别、文件和行、复现条件、实际影响以及建议的修复方向。然后说明已检查范围和限制。如果没有已确认的问题，请明确说明并指出审查范围的局限。
```
