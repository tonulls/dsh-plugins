# 提示词示例：`/ecc-type-design-analyzer`

**调用命令：** `/ecc-type-design-analyzer`

## 用途

分析类型设计：封装、不变量表达、实际效用以及如何强制执行不变量。

## 1. 简短请求

```text
/ecc-type-design-analyzer 分析 {路径} 中的类型不变量；不要修改代码。
```

## 2. 模板请求

```text
/ecc-type-design-analyzer 评估领域 {背景} 中的类型 {文件/片段}。对每个关键类型，检查它允许哪些无效状态、不变量是否在 API 中表达，以及谁可能破坏这些不变量。提出备选方案并说明权衡；不要修改代码。
```

## 3. 详细请求

```text
/ecc-type-design-analyzer 请针对任务 {场景/更改} 执行分步分析。

1. 记录初始背景，仅研究相关材料。
2. 检查此角色关注的关键风险和标准：封装、不变量表达、实际效用及其强制执行方式。
3. 区分已确认的事实与推测，并指出缺失的信息。
4. 生成按优先级排序的结果，附上证据、验证限制和具体后续步骤。

边界：不要泄露机密或个人数据；未经明确许可，不要执行网络操作、安装软件包、部署或运行潜在危险的命令。分析期间不要修改文件；任何更改、删除、启动循环或应用配置的操作，都必须先协商并等待我的确认。
```
