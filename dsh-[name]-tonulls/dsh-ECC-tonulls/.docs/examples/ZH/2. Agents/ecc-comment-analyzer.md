# `/ecc-comment-analyzer` — 提示词示例

## 用途

分析代码注释的事实准确性、上下文充分性、可维护性和过时风险。目标是找出可能误导读者，或未能帮助理解复杂决策的注释。

## 1. 简短请求

```text
/ecc-comment-analyzer 检查 {文件/模块} 中的注释：找出错误、过时或无用的内容，并说明风险。不要进行任何更改。
```

## 2. 模板请求

```text
/ecc-comment-analyzer 分析 {路径/diff} 中的注释是否符合当前实现。对每处可疑内容，将注释与代码进行对照，注明文件/行和类别：不准确、不完整、冗余或 comment rot 风险。提出改写建议或删除建议，但不要编辑文件。
```

## 3. 详细请求

```text
/ecc-comment-analyzer 以只读方式审计 {路径或已修改文件} 中的注释。更改/模块背景：{用途（如已知）}。

1. 将每条重要注释与实际逻辑、契约和相邻符号进行对照，检查其是否描述了旧行为。
2. 评估注释是否解释了必要的原因、限制或不变量，还是仅复述了显而易见的代码。
3. 对每项风险标注类别——事实错误、缺少重要背景、可维护性困难/comment rot 或多余注释——并提供相邻实现中的证据。
4. 区分已证实的过时内容和疑点；说明解决不确定情况需要何种检查或背景。

格式：按优先级列出文件和行、当前措辞（不要泄露机密）、可证实的差异/风险以及建议操作：修正、补充或删除。最后说明审计范围和限制。不要修改源代码或注释，不要安装软件包、访问网络或部署。
```
