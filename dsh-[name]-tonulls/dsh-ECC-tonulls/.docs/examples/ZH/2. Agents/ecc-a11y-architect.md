# `/ecc-a11y-architect`

依据 WCAG 2.2 设计并检查 Web 和原生界面的无障碍性：组件、设计系统和包容性。

## 简单请求

```text
/ecc-a11y-architect 按照 WCAG 2.2 检查注册表单的无障碍性，并列出主要问题。不要进行任何更改。
```

## 模板请求

```text
/ecc-a11y-architect 评估 [屏幕/组件]（位于 [路径/描述]）的无障碍性。用户背景：[受众]；平台：[web/native]。检查语义、键盘导航、焦点和反馈。仅做分析，不要修改文件；提供依据并排列优先级。
```

## 详细请求

```text
/ecc-a11y-architect 按照 WCAG 2.2 审计 [平台] 上的 [组件/流程] 的无障碍性。
1. 研究相关组件及其状态。
2. 检查语义、键盘/焦点控制、无障碍名称、错误处理以及对辅助技术的适配。
3. 对每项发现说明证据、受影响的场景和估计严重程度；将未知事项标注为需要人工检查。
4. 提出修复建议和工作顺序，但不要编辑文件。
报告应包含简要结论、发现列表、对应标准、建议及验证限制。未经我许可，不要访问网络或使用其他工具。
```
