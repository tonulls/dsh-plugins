# `/ecc-nestjs-patterns`

**Purpose:** NestJS architecture practices: modules, controllers, providers, DTO validation, guards, interceptors, configuration, and production TypeScript server applications. Use when developing or reviewing NestJS backends.

## Short Prompt
```text
/ecc-nestjs-patterns Review NestJS module [path], focusing on DTO validation, guards, and module boundaries.
```

## Template Prompt
```text
/ecc-nestjs-patterns
Context: [project path / snippet / system / symptom].
Task: review the architecture of a server-side NestJS module for [goal or subject].
Focus: modules/controllers/providers, DTO validation, guards, interceptors, configuration, and server-side boundaries.
Constraints: Read-only: do not modify files or run active/external checks.
Output format: [brief conclusion, evidence, priorities, and next steps].
```

## Detailed Prompt
```text
/ecc-nestjs-patterns
Perform the task “review the architecture of a server-side NestJS module” for [project/component/scenario].
1. Record baseline information, scope, and success criteria; list missing information.
2. Study only relevant context and assess modules/controllers/providers, DTO validation, guards, interceptors, configuration, and server-side boundaries.
3. Form conclusions and next steps without applying changes or presenting assumptions as facts.
4. Compare results with criteria, cite evidence, and distinguish confirmed conclusions from assumptions.

Constraints: Read-only: do not modify files or run active/external checks.
Include outcome, important findings/actions, unverified areas, risks, and safe next steps.
```
