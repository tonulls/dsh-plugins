# `/ecc-coding-standards`

**Purpose:** Baseline coding conventions across projects: naming, readability, immutability, and quality checks. For specialized practices, use more detailed frontend/backend skills. Apply when assessing quality or naming and no suitable framework-specific skill exists.

## Short Prompt
```text
/ecc-coding-standards Review changed code for baseline readability, naming, and immutability standards; do not duplicate framework-specific rules.
```

## Template Prompt
```text
/ecc-coding-standards
Context: [project path / snippet / system / symptom].
Task: review baseline conventions when there is no more specific framework skill for [goal or subject].
Focus: naming, readability, immutability, and consistent quality criteria.
Constraints: Read-only: do not modify files or run active/external checks.
Output format: [brief conclusion, evidence, priorities, and next steps].
```

## Detailed Prompt
```text
/ecc-coding-standards
Perform the task “review baseline conventions when no more specific framework skill exists” for [project/component/scenario].
1. Record baseline information, scope, and success criteria; list missing information.
2. Study only relevant context and assess naming, readability, immutability, and consistent quality criteria.
3. Form conclusions and next steps without applying changes or presenting assumptions as facts.
4. Compare results with criteria, cite evidence, and distinguish confirmed conclusions from assumptions.

Constraints: Read-only: do not modify files or run active/external checks.
Include outcome, important findings/actions, unverified areas, risks, and safe next steps.
```
