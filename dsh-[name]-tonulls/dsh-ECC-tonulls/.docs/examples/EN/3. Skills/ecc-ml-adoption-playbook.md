# `/ecc-ml-adoption-playbook`

**Purpose:** A methodology for adding machine learning to existing non-ML projects for AI agents and engineers: problem definition, data readiness, architectural separation, and baseline model integration. Use when adding ML capabilities, from framing the problem to the first model.

## Short Prompt
```text
/ecc-ml-adoption-playbook Suggest a path from business problem [goal] to the first verifiable ML model in an existing application.
```

## Template Prompt
```text
/ecc-ml-adoption-playbook
Context: [project path / snippet / system / symptom].
Task: plan the adoption of an ML capability in an existing project for [goal or subject].
Focus: problem definition, data quality/availability, baseline model, architectural boundaries, and evaluation criteria.
Constraints: Provide recommendations; do not apply changes, send messages, or publish.
Output format: [brief conclusion, evidence, priorities, and next steps].
```

## Detailed Prompt
```text
/ecc-ml-adoption-playbook
Perform the task “plan the adoption of an ML capability in an existing project” for [project/component/scenario].
1. Record baseline information, scope, and success criteria; list missing information.
2. Study only relevant context and assess problem definition, data quality/availability, baseline model, architectural boundaries, and evaluation criteria.
3. Form conclusions and next steps without applying changes or presenting assumptions as facts.
4. Compare results with criteria, cite evidence, and distinguish confirmed conclusions from assumptions.

Constraints: Provide recommendations; do not apply changes, send messages, or publish.
Include outcome, important findings/actions, unverified areas, risks, and safe next steps.
```
