# `/ecc-command-test-coverage`

**Назначение:** проанализировать имеющееся покрытие, выявить непокрытые функции, ветви и граничные случаи, а затем добавить недостающие тесты в явно заданной области проекта. Используются только доступные локально инструменты и существующие соглашения проекта; установка/загрузка пакетов запрещена.

## Примеры промтов

### 1. Короткий запрос

```text
/ecc-command-test-coverage Проанализируй покрытие модуля валидации заказов и добавь недостающие тесты только для него. Не устанавливай зависимости.
```

### 2. Запрос с контекстом

```text
/ecc-command-test-coverage
Проверь покрытие компонента [путь/название] в проекте [путь или репозиторий]. Найди доступную локальную команду покрытия, сравни показатели по файлам и сначала сосредоточься на [важные функции, ветви или ошибки].

Добавляй тесты только в [точная область], следуя принятому в проекте расположению и стилю. Ограничение целевого покрытия: [например, 80% / только улучшить текущий показатель]. Не меняй производственный код без отдельного согласования. Используй лишь уже установленные средства; не запускай npx с загрузкой кода и не устанавливай пакеты. Если покрытие нельзя измерить имеющимися инструментами, сообщи об этом вместо установки.
```

### 3. Подробный запрос

```text
/ecc-command-test-coverage
Проанализируй и улучши тестовое покрытие для [папка/модуль] с целью [порог или конкретное улучшение]. Выполняй работу последовательно:
1. Определи тестовый фреймворк и доступный локальный инструмент покрытия по конфигурации проекта. Не скачивай инструменты и пакеты; если подходящего инструмента нет, остановись и укажи ограничение.
2. Получи исходные показатели и составь список файлов ниже целевого порога, начиная с наименее покрытых. Для каждого выдели непроверенные функции, ветви, обработку ошибок и граничные случаи.
3. Предложи тесты в порядке приоритета: основной сценарий, ошибки, крайние значения/пустые данные и оставшиеся ветви. Добавляй их только в [точно разрешенная область], используя существующие шаблоны, утверждения и подходы к мокам. Не включай реальные секреты и не отправляй данные во внешние сервисы.
4. Запусти доступную локальную тестовую команду, затем повторно измерь покрытие. Не изменяй исходную функциональность или конфигурацию и не создавай файлы вне области тестов без предварительного согласия. Удаление/перезапись файлов и любые действия с побочными эффектами требуют отдельного подтверждения.
5. Подготовь отчет: покрытие до/после по измененным целевым файлам и общее (если доступно), какие сценарии добавлены, какие проверки выполнены и их результат, оставшиеся пробелы и препятствия.

Если тесты не проходят или улучшение потребовало бы изменения приложения, остановись, опиши причину и запроси согласование дальнейших действий.
```
