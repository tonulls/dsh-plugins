# `/ecc-command-update-docs`

**Назначение:** синхронизировать документацию с фактическими источниками истины проекта — например, скриптами, переменными-шаблонами окружения, маршрутами, схемами и публичными экспортами. Изменения ограничиваются явно запрошенными документами; автоматически запускаемые генераторы не выполняются.

## Примеры промтов

### 1. Короткий запрос

```text
/ecc-command-update-docs Обнови таблицу команд в документации по скриптам package.json; не меняй другие разделы.
```

### 2. Запрос с контекстом

```text
/ecc-command-update-docs
Сверь документацию [путь к документу] с источником истины [package.json / схема API / маршруты / публичные экспорты]. Обнови только раздел [название раздела], сохранив авторские пояснения и существующее форматирование.

Не создавай дополнительные документы и не запускай генераторы или скрипты проекта. Если нужные факты отсутствуют или требуют предположений, перечисли вопросы вместо того, чтобы придумывать значения. Любые изменения вне указанного раздела, удаление или перезапись других файлов сначала согласуй со мной.
```

### 3. Подробный запрос

```text
/ecc-command-update-docs
Приведи документацию [путь/раздел] в соответствие с текущими исходниками для [область: команды, переменные окружения, API-маршруты, экспорты или инфраструктурная конфигурация]. Работай по этапам:
1. Найди соответствующие источники истины и прочитай их; не выводи поведение, значения или процедуры из догадок.
2. Составь перечень расхождений между исходниками и документацией, указав затронутые места и фактические основания.
3. Измени только [точный файл и разделы]. Сохрани вручную написанный текст и обновляй лишь относящиеся к запросу сведения. Не создавай новые документы, не запускай проектные генераторы и не меняй исходники/конфигурацию.
4. Если для точности не хватает данных, оставить старые сведения безопаснее, или правка выходит за область — остановись и запроси уточнение/подтверждение. Удаление, переименование и перезапись файлов не выполняй без моего отдельного явного согласия.
5. В отчете перечисли измененные разделы и источники, подтверждающие содержание; отдельно укажи неразрешенные расхождения и пропущенные сведения. Если изменений не потребовалось, сообщи об этом.

Не публикуй и не отправляй документацию во внешние системы.
```
