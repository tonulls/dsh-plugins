# `/ecc-command-build-fix`

**Назначение:** определить используемую в проекте систему сборки, последовательно диагностировать ошибки сборки и типов и устранять их минимальными безопасными изменениями. Применяются только уже доступные инструменты; установка или загрузка зависимостей не выполняется.

## Примеры промтов

### 1. Короткий запрос

```text
/ecc-command-build-fix Найди и минимально исправь текущие ошибки сборки. Используй только уже установленные инструменты; зависимости не устанавливай.
```

### 2. Запрос с контекстом

```text
/ecc-command-build-fix
В проекте [путь или название модуля] сборка завершается ошибками. Проверь систему сборки и локально доступную команду, затем разбери ошибки по файлам и устраняй их по одной минимальными правками.

Область: [каталоги/модули]. Не меняй архитектуру и файлы вне этой области. Не устанавливай и не загружай пакеты. Если нужного инструмента нет, ошибка повторяется после трех попыток или требуется широкое изменение — остановись и объясни причину; прежде чем продолжать такие изменения, запроси подтверждение.
```

### 3. Подробный запрос

```text
/ecc-command-build-fix
Исправь ошибки сборки/типов для [проект или целевой модуль]. Работай по этапам:
1. Определи систему сборки по файлам проекта и выбери только уже установленную локальную команду проверки.
2. Выполни проверку и сгруппируй сообщения об ошибках по файлам; укажи исходное число ошибок.
3. Для каждой ошибки изучи контекст, установи первопричину и предложи/внеси наименьшую правку в пределах [разрешенная область]. После каждой правки повтори проверку и оцени, не появились ли новые ошибки.
4. Остановись, если инструмент/зависимость отсутствует, ошибка не устранена за три попытки, исправление добавляет больше ошибок, затрагивает архитектуру или выходит за пределы области. Ничего не устанавливай, не скачивай и не запускай сетевые действия. Перед удалением данных, публикацией или иным существенным побочным действием сначала запроси отдельное подтверждение.
5. В конце сообщи выполненные изменения с путями, результаты повторных проверок, оставшиеся и новые ошибки (если есть), а также безопасные следующие шаги.

Не проводи несвязанный рефакторинг и не изменяй файлы вне указанной области без моего предварительного согласия.
```
