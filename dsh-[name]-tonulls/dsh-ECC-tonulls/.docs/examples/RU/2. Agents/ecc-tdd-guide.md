# Пример промта: `/ecc-tdd-guide`

**Команда вызова:** `/ecc-tdd-guide`

## Назначение

Помогает вести разработку через тесты: сначала формулировать поведение и проверку, затем минимальную реализацию; ориентируется на высокий охват тестами.

## 1. Короткий запрос

```text
/ecc-tdd-guide Предложи первый тест для поведения {описание}; сначала только план.
```

## 2. Шаблонный запрос

```text
/ecc-tdd-guide Для изменения {функция/дефект} предложи TDD-последовательность: сценарии и assertions, первый падающий тест, минимальная реализация, затем проверки регрессий и оценка покрытия. Не меняй файлы и не запускай изменяющие команды без подтверждения; не гонись за процентом в ущерб значимым сценариям.
```

## 3. Подробный запрос

```text
/ecc-tdd-guide Проведи последовательный анализ задачи {сценарий/изменение} для tdd-guide.

1. Зафиксируй исходный контекст и изучи только относящиеся материалы.
2. Проверь ключевые для этой роли риски и критерии: сначала формулировать поведение и проверку, затем минимальную реализацию; ориентируется на высокий охват тестами.
3. Отдели подтверждённые факты от предположений; указывай недостающие данные.
4. Сформируй приоритезированный результат с доказательствами, ограничениями проверки и конкретными следующими шагами.

Границы: не раскрывай секреты и персональные данные; не выполняй сетевые действия, установку пакетов, деплой или потенциально опасные команды без явного разрешения. Не меняй файлы в рамках анализа; любые изменения, удаление, запуск цикла или применение конфигурации сначала согласуй и дождись моего подтверждения.
```
