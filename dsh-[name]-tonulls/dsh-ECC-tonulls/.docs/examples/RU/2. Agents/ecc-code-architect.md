# `/ecc-code-architect` — примеры промтов

## Назначение

Изучает существующие шаблоны кодовой базы и готовит конкретный план реализации функции: файлы, интерфейсы, поток данных и порядок сборки. Это blueprint для разработчика, а не самостоятельная реализация.

## 1. Короткий запрос

```text
/ecc-code-architect Подготовь план реализации {функции} по существующим соглашениям проекта: файлы, интерфейсы и порядок работ. Код не меняй.
```

## 2. Шаблонный запрос

```text
/ecc-code-architect Спроектируй реализацию {функция/изменение} в {путь проекта}. Изучи существующие образцы в {релевантные области}. Условия: {контракт, ограничения, совместимость}. Дай перечень файлов, интерфейсы и поток данных, этапы, зависимости между ними и критерии проверки. Только план, никаких правок.
```

## 3. Подробный запрос

```text
/ecc-code-architect Подготовь blueprint для {функциональность и ожидаемые сценарии} в {проект}. Контекст: {пользователи, входы/выходы, интеграции}; ограничения: {совместимость, производительность, безопасность, область изменений}.

1. Найди и изучи существующие реализации аналогичных компонентов и проектные соглашения; подкрепляй выводы путями к файлам и символами.
2. Проследи затрагиваемый поток данных и границы модулей. Определи необходимые интерфейсы, типы/контракты и обработку ошибок, не придумывая отсутствующие требования.
3. Составь таблицу «файл/область | предполагаемая роль | изменение | зависимость». Не включай файлы, необходимость которых не обоснована.
4. Упорядочи реализацию так, чтобы зависимости и проверяемые промежуточные результаты были явны; перечисли проверки и пограничные случаи.
5. Отдельно перечисли архитектурные риски, допущения и решения, которые нужно подтвердить до кодирования.

Формат: краткий обзор, основания в кодовой базе, blueprint файлов и интерфейсов, поток данных, порядок работ, проверки, риски и вопросы. Не редактируй файлы и не запускай реализацию; установка, сеть и деплой запрещены без отдельного согласия.
```
