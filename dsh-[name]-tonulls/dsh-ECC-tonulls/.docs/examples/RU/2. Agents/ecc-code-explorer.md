# `/ecc-code-explorer` — примеры промтов

## Назначение

Исследует существующую кодовую базу: прослеживает путь выполнения, отображает архитектурные слои и зависимости, чтобы дать проверяемый контекст для дальнейшей разработки. Не реализует изменения.

## 1. Короткий запрос

```text
/ecc-code-explorer Проследи, как {сценарий} проходит через проект: точки входа, слои и зависимости. Ничего не меняй.
```

## 2. Шаблонный запрос

```text
/ecc-code-explorer Исследуй в {путь проекта} функцию {название/сценарий}. Найди точку входа и проследи вызовы до {интересующий результат или интеграция}; опиши задействованные слои, файлы и зависимости с указанием символов. Отдели подтверждённое от предположений; изменения не вноси.
```

## 3. Подробный запрос

```text
/ecc-code-explorer Проведи анализ существующей реализации сценария {сценарий} в {путь проекта}, чтобы подготовить контекст для {следующее решение/разработка}.

1. Найди пользовательскую или системную точку входа и опиши, как она обнаружена.
2. Проследи фактические пути выполнения: вызовы, условные ветви, обработку ошибок, доступ к данным и внешние интеграции. Укажи файлы, символы и значимые переходы между слоями.
3. Составь карту компонентов и зависимостей, относящихся к сценарию; обозначь границы того, что не исследовалось.
4. Сопоставь утверждения с исходным кодом и тестами, если они доступны. Не делай выводов о runtime-поведении, которое не подтверждено просмотром или разрешённой проверкой.
5. Заверши кратким резюме потока, точками расширения и вопросами, которые нужно выяснить перед изменением.

Формат: резюме, схема текстом «вход → компоненты → результат», таблица компонентов/файлов и зависимостей, доказательства, пробелы. Только чтение: не редактируй файлы, не устанавливай пакеты, не обращайся к сети и не выполняй деплой.
```
