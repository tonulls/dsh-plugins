# `ecc-security-reviewer` — примеры промтов

Примеры для явного вызова роли проверки безопасности. Отправляйте команду и задачу одним обычным сообщением DSH. Формулировку можно адаптировать под стек и нужную часть проекта.

## 1. Простой и короткий

```text
/ecc-security-reviewer Быстро проверь текущий проект на очевидные проблемы безопасности. Ничего не меняй. Для каждой найденной проблемы укажи файл, строки и возможный риск.
```

## 2. Обычный шаблонный

```text
/ecc-security-reviewer Проведи read-only аудит безопасности проекта <путь-к-проекту> на стеке <язык-и-фреймворк>. Проверь обработку пользовательского ввода, аутентификацию и авторизацию, хранение секретов, работу с файлами и внешними командами, а также зависимости. Не изменяй файлы и не устанавливай пакеты. Для каждого подтверждённого замечания укажи серьёзность, точные файл и строки, сценарий риска и способ исправления. В конце перечисли, что осталось непроверенным.
```

## 3. Подробный поэтапный

```text
/ecc-security-reviewer Проведи поэтапный read-only аудит безопасности проекта <путь-к-проекту> (стек: <язык-и-фреймворк>).

1. Сначала кратко опиши границы проверки и основные точки входа: маршруты/API, авторизацию, обработчики пользовательских данных, загрузку и распаковку файлов, запуск процессов, хранение секретов.
2. Проследи потоки данных от внешнего ввода до чувствительных операций; при каждом подозрении проверь вызывающий код, проверки доступа, обработку ошибок и относящиеся к нему тесты.
3. Проверь зависимости и доступные локальные средства только для фактического стека проекта. Не запускай нерелевантные команды, не устанавливай пакеты и не обращайся к сети без отдельного разрешения.
4. Ничего не изменяй. Не считай совпадение по поисковому шаблону уязвимостью без подтверждённого сценария эксплуатации.

В отчёте раздели подтверждённые проблемы и предположения. Для каждой проблемы укажи уровень серьёзности, файл и строки, необходимые условия атаки, влияние и рекомендуемое исправление. Отдельно перечисли проверенные файлы/области, выполненные проверки и оставшиеся пробелы. Не объявляй аудит полным, если какие-либо значимые области не проверены.
```
