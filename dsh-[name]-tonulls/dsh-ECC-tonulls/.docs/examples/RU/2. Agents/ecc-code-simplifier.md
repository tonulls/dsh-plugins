# `/ecc-code-simplifier` — примеры промтов

## Назначение

Упрощает недавно изменённый или явно указанный код, улучшая ясность, согласованность и сопровождаемость при сохранении поведения. Объём следует ограничивать целевыми фрагментами.

## 1. Короткий запрос

```text
/ecc-code-simplifier Упрости {файл/фрагмент} без изменения поведения. Не расширяй область правок; объясни результат.
```

## 2. Шаблонный запрос

```text
/ecc-code-simplifier Приведи в порядок {пути или недавно изменённый участок} в контексте {цель кода}. Сохрани публичные контракты и поведение, избегай архитектурной переработки. Меняй только {разрешённая область}; перед выходом перечисли изменения и доступные подтверждения сохранения поведения. Установка пакетов и сеть запрещены.
```

## 3. Подробный запрос

```text
/ecc-code-simplifier Упрости {конкретные файлы/изменённый фрагмент} ради {ясность/согласованность/сопровождаемость}. Считай внешнее поведение и контракты неизменными. Ограничения: {разрешённые файлы, стиль проекта, совместимость}.

1. Сначала определи фактические границы целевого кода и изучи его вызовы, типы и существующие соглашения.
2. Выдели только очевидные улучшения ясности или устранение локального дублирования; объясни, почему каждое сохраняет поведение.
3. Не меняй публичные API, архитектуру, формат данных, обработку ошибок или соседние модули без необходимости и отдельного согласия.
4. Внеси минимальные локальные правки только в разрешённой области. Если упрощение требует изменения поведения или расширения объёма — остановись, изложи вариант и запроси подтверждение.
5. Не устанавливай пакеты, не используй сеть и не выполняй деплой. Не запускай тесты/проверки без разрешения; не заявляй о проверке, которую не выполнял.

Формат ответа: что упрощено и почему, какие контракты сохранены, список изменённых файлов, подтверждения/проверки и оставшиеся риски. При невозможности безопасно упростить участок оставь его без изменений и объясни причину.
```
