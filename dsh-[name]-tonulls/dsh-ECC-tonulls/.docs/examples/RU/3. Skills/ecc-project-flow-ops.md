# `/ecc-project-flow-ops`

**Назначение:** Управляет процессом работы в GitHub и Linear: сортирует issues и pull requests, связывает активные задачи, оставляет GitHub публичным интерфейсом, а Linear — внутренним инструментом исполнения. Используйте для управления бэклогом, сортировки PR и координации GitHub с Linear.

## Короткий промт

```text
/ecc-project-flow-ops Подготовь план triage для [issues/PR], связав публичный GitHub с внутренним Linear; ничего не меняй.
```

## Шаблонный промт

```text
/ecc-project-flow-ops
Контекст: [список issue/PR, связанные Linear-тикеты, критерии приоритета и ограничения доступа].
Задача: скоординировать triage задач и PR между GitHub и Linear для [целевой компонент/результат].
Фокус: статусы, связи активной работы, приоритеты backlog, публичные/внутренние границы и отсутствие публикации без разрешения.
Ограничения: Составь план и критерии проверки; не меняй код, данные, расписание или внешние системы.
Формат: [краткий итог, доказательства/обоснования, риски и следующий шаг].
```

## Подробный промт

```text
/ecc-project-flow-ops
Выполни задачу «скоординировать triage задач и PR между GitHub и Linear» для [целевая система/сценарий].
1. Уточни цель, scope, исходные сведения и критерии результата; перечисли недостающий контекст.
2. Изучи только относящиеся к запросу материалы и проверь: статусы, связи активной работы, приоритеты backlog, публичные/внутренние границы и отсутствие публикации без разрешения.
3. Сформулируй находки или варианты с фактами, рисками, критериями проверки и неразрешёнными вопросами; ничего не применяй.
4. Проверь выводы по заданным критериям, укажи доказательства, допущения и непроверенное.

Ограничения: Составь план и критерии проверки; не меняй код, данные, расписание или внешние системы.
Оформи результат так: [ожидаемый формат]. Не придумывай факты; перед любым непредусмотренным побочным действием остановись и запроси согласие.
```
