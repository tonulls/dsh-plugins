# `/ecc-api-connector-builder`

Добавляет API-коннектор или провайдера, следуя уже принятому в репозитории шаблону интеграций, а не вводя параллельную архитектуру.

## Примеры промтов

### 1. Короткий запрос
```text
/ecc-api-connector-builder Добавь коннектор для [провайдер] по образцу существующих интеграций проекта. Сначала изучи локальный шаблон.
```

### 2. Шаблонный запрос
```text
/ecc-api-connector-builder Реализуй интеграцию [сервис/API] в [проект]. Аналог для изучения: [путь или название]. Требуемые операции: [список]. Изменяй только относящиеся к коннектору файлы, не устанавливай зависимости и не обращайся к сети; если шаблон или контракт неясен — остановись и укажи вопрос.
```

### 3. Подробный запрос
```text
/ecc-api-connector-builder Создай коннектор [провайдер] для [репозиторий/модуль]. 1) Найди и разберись с существующим коннектором: интерфейс, конфигурация, ошибки, сериализация и тестовый подход. 2) Сверь доступные локально требования API и перечисли пробелы, не выдумывая эндпоинты. 3) Реализуй только необходимые файлы интеграции в том же стиле; не меняй несвязанные модули, не устанавливай пакеты и не выполняй сетевые запросы. 4) Проверь diff и сообщи, какие проверки не запускались. Итог: использованный образец, перечень изменений, допущения и ограничения.
```
