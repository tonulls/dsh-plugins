# `/ecc-tdd-workflow`

Проводит разработку через цикл TDD: сначала падающий тест, затем минимальное изменение до зеленого результата и рефакторинг с целевым покрытием unit/integration/E2E.

## Простой запрос
```text
/ecc-tdd-workflow Исправь [дефект] через TDD: сначала сформулируй тест, который его воспроизводит.
```
## Шаблонный запрос
```text
/ecc-tdd-workflow
Задача и критерии приемки: [описание]
Код и существующие тесты: [пути/фрагмент]
Ограничения: [совместимость/покрытие]
Предложи цикл red-green-refactor и тесты для важных границ.
```
## Подробный запрос
```text
/ecc-tdd-workflow
Выполни задачу [описание] по TDD. 1) Уточни критерии приемки и существующую структуру тестов. 2) Спроектируй минимальный тест, который должен падать на текущем поведении. 3) После моего подтверждения внеси тест и запусти только согласованную команду. 4) Реализуй минимальную правку и повтори тест. 5) Рефактори, сохраняя зеленое состояние; оцени unit/integration/E2E пробелы и целевое покрытие. Не устанавливай пакеты, не обращайся к сети, не деплой и не изменяй несвязанные файлы. Если тесты или правка затрагивают данные/внешние системы, остановись и запроси подтверждение. Отчет: изменения, red/green доказательства, реально выполненные команды и остаточные риски.
```
