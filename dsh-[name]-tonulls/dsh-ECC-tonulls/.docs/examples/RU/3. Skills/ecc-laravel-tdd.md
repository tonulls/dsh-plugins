# ecc-laravel-tdd

**Команда:** `/ecc-laravel-tdd`

**Назначение:** Разработка и исправление тестов Laravel с PHPUnit или Pest: фабрики моделей, HTTP-тесты, проверка Sanctum-аутентификации, моки и покрытие; также ведение функции от теста.

## Промты

### 1. Короткий запрос

> /ecc-laravel-tdd Напиши Pest-тест для этого Laravel HTTP endpoint: проверь успешный ответ и отказ без нужных прав, используя существующие фабрики проекта.

### 2. Шаблон с заполнителями

> /ecc-laravel-tdd Для [функция/endpoint] добавь тесты на [успешный сценарий, ошибки, права доступа]. В проекте используются [PHPUnit/Pest], фабрики [модели], авторизация [Sanctum/другое]. Сначала изучи существующие соглашения и тестовые вспомогательные средства. Изменяй только тесты [перечень путей]; не устанавливай зависимости и не меняй production-код без отдельного согласия.

### 3. Подробный поэтапный запрос

> /ecc-laravel-tdd Проведи тест-first работу для сценария [описание] в Laravel. 1) Найди аналогичные тесты, конфигурацию PHPUnit/Pest и фабрики; уточни границы тестируемого поведения. 2) Составь матрицу случаев: валидный запрос, ошибки валидации, отсутствие/недостаточность авторизации, побочные эффекты и границы данных. 3) Добавь минимальные изолированные тесты, предпочитая фабрики и HTTP-поверхность там, где проверяется endpoint; моки используй только для внешних границ. 4) Покажи команды проверки, но не запускай их без необходимости/согласия. В конце перечисли изменённые файлы, покрытые ожидания и непроверенные случаи. Не меняй код приложения, не устанавливай пакеты, не используй сеть.
