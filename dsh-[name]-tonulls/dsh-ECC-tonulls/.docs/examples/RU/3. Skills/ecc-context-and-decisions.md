# `/ecc-context-and-decisions`

Помогает закреплять устойчивые предметные термины и контекст в узко ограниченном `CONTEXT.md`, отделяя их от труднообратимых архитектурных решений, для которых предназначен ADR.

## Простой запрос

```text
/ecc-context-and-decisions В команде термин «рабочая область» означает разные сущности; предложи, как зафиксировать единое значение.
```

## Шаблонный запрос

```text
/ecc-context-and-decisions
Домен/модуль: [название]
Термин или повторяющийся контекст: [описание]
Разные трактовки и последствия: [примеры]
Текущая структура документации: [пути]
Предложи узкий контекстный документ или укажи, что это архитектурное решение для ADR.
```

## Подробный запрос

```text
/ecc-context-and-decisions
Проанализируй проблему неоднозначного доменного языка в [модуль/проект]. 1) Собери термины и примеры из предоставленных материалов. 2) Раздели устойчивые определения предметной области и решения о структуре/технологиях. 3) Предложи минимальный CONTEXT.md только для контекста, который действительно нужен повторно, и направь труднообратимые решения в имеющийся процесс ADR. 4) Отметь последствия для границ модулей и открытые вопросы. Не создавай и не редактируй файлы без моего подтверждения; сначала покажи проект текста и рекомендуемое место с учётом существующей документации. Итог — словарь терминов, классификация и предложение изменений.
```
