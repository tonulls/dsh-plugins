# `/ecc-product-capability`

**Назначение:** Преобразует намерения из PRD, запросы дорожной карты и обсуждения продукта в готовый к реализации план возможностей: фиксирует ограничения, инварианты, интерфейсы и нерешённые вопросы до начала межсервисной работы. Используйте для структурированного перехода от PRD к SRS в ECC вместо расплывчатого плана.

## Короткий промт

```text
/ecc-product-capability Преобразуй [PRD/идею] в план capability с интерфейсами, инвариантами и открытыми решениями.
```

## Шаблонный промт

```text
/ecc-product-capability
Контекст: [PRD/roadmap/обсуждение, целевые пользователи, затронутые системы и ограничения].
Задача: преобразовать продуктовое намерение в готовый к реализации план capability для [целевой компонент/результат].
Фокус: пользователи, ограничения, инварианты, интерфейсы между сервисами и решения, требующие владельца продукта.
Ограничения: Подготовь аналитический документ в ответе; не создавай файлы и не начинай реализацию без согласия.
Формат: [краткий итог, доказательства/обоснования, риски и следующий шаг].
```

## Подробный промт

```text
/ecc-product-capability
Выполни задачу «преобразовать продуктовое намерение в готовый к реализации план capability» для [целевая система/сценарий].
1. Уточни цель, scope, исходные сведения и критерии результата; перечисли недостающий контекст.
2. Изучи только относящиеся к запросу материалы и проверь: пользователи, ограничения, инварианты, интерфейсы между сервисами и решения, требующие владельца продукта.
3. Сформулируй целевую capability/spec с инвариантами, интерфейсами, acceptance criteria и открытыми решениями; отдели факты от гипотез.
4. Проверь выводы по заданным критериям, укажи доказательства, допущения и непроверенное.

Ограничения: Подготовь аналитический документ в ответе; не создавай файлы и не начинай реализацию без согласия.
Оформи результат так: [ожидаемый формат]. Не придумывай факты; перед любым непредусмотренным побочным действием остановись и запроси согласие.
```
