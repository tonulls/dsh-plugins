# `/ecc-browser-qa`

Автоматизированная проверка развернутого интерфейса через доступный browser automation MCP (claude-in-chrome, Playwright или Puppeteer): ошибки консоли, Core Web Vitals, сценарии форм и аутентификации, визуальная регрессия на трёх ширинах, аудит axe-core и итог SHIP / DO-NOT-SHIP.

## Короткий запрос

```text
/ecc-browser-qa Проверь staging-страницу оформления заказа: основные ошибки, форму, доступность и адаптивность; заверши вердиктом SHIP или DO-NOT-SHIP.
```

## Шаблон

```text
/ecc-browser-qa Проведи браузерную QA deployed-версии [URL/окружение] для изменения [функция/PR]. Используй доступный MCP [инструмент, если известен]. Проверь [сценарии, включая формы/auth], консоль, Core Web Vitals, три ширины [значения] и axe-core. Не выполняй опасных действий с реальными данными и не меняй продакшен.
```

## Поэтапный запрос

```text
/ecc-browser-qa Проверь feature [название] на [staging/preview URL], связанный PR [идентификатор]. Условия: тестовые учётные данные [без секретов в отчёте], безопасные тестовые данные [описание].
1. Убедись, что доступен browser automation MCP и целевой URL действительно относится к staging/preview; если нет — остановись и сообщи ограничение.
2. Зафиксируй ошибки консоли и доступные метрики Core Web Vitals.
3. Выполни согласованные сценарии форм и входа/выхода, не отправляя реальных платежей, сообщений или изменений аккаунта.
4. Сравни визуальный результат на узком, среднем и широком breakpoint; сохрани скриншоты/ссылки только если инструмент это поддерживает.
5. Запусти axe-core аудит, сгруппируй нарушения по серьёзности и укажи воспроизводимые шаги.

Итог: таблица проверок со статусом и доказательствами, дефекты с шагами воспроизведения и однозначный SHIP / DO-NOT-SHIP. Не утверждай о проверках, которые инструмент не выполнил. Никаких деплоев/изменений окружения без согласия.
```
