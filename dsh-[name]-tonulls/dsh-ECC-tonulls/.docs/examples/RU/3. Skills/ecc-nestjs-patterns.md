# `/ecc-nestjs-patterns`

**Назначение:** Архитектурные практики NestJS: модули, контроллеры, провайдеры, валидация DTO, защитные механизмы, перехватчики, конфигурация и серверные приложения TypeScript для рабочей среды. Используйте при разработке или проверке серверной части NestJS.

## Короткий промт

```text
/ecc-nestjs-patterns Проведи ревью NestJS-модуля [путь], уделяя внимание DTO-валидации, guards и границам модулей.
```

## Шаблонный промт

```text
/ecc-nestjs-patterns
Контекст: [путь к проекту / фрагмент / система / симптом].
Задача: проверить архитектуру серверного NestJS-модуля для [цель или объект].
Фокус: modules/controllers/providers, DTO validation, guards, interceptors, config and server-side boundaries.
Ограничения: Только чтение: не меняй файлы, не запускай активные или внешние проверки.
Формат результата: [краткий вывод, подтверждения, приоритеты и следующие шаги].
```

## Подробный промт

```text
/ecc-nestjs-patterns
Выполни задачу «проверить архитектуру серверного NestJS-модуля» для [проект/компонент/сценарий].
1. Зафиксируй исходные данные, область работы и критерии результата; перечисли недостающие сведения.
2. Изучи только относящийся к задаче контекст и проверь: modules/controllers/providers, DTO validation, guards, interceptors, config and server-side boundaries.
3. Сформулируй выводы и следующие шаги, не применяя изменений и не выдавая предположения за факты.
4. Сопоставь результат с критериями, укажи доказательства и отдели подтверждённые выводы от предположений.

Ограничения: Только чтение: не меняй файлы, не запускай активные или внешние проверки.
В отчёте укажи итог, важные находки/действия, непроверенные части, риски и безопасные следующие шаги.
```
