# `/ecc-benchmark`

Измеряет и сопоставляет производительность по воспроизводимым базовым показателям: Core Web Vitals и вес страницы, перцентили задержки API, время сборки и обратной связи тестов. Результаты до/после сохраняются в git-отслеживаемый JSON в `.ecc/benchmarks`.

## Примеры промтов

### 1. Короткий запрос
```text
/ecc-benchmark Сними воспроизводимый baseline для [страница/API/сборка] и укажи метрики и условия измерения. Ничего не публикуй и не деплой.
```

### 2. Шаблонный запрос
```text
/ecc-benchmark Сравни производительность [цель] до и после [изменение]. Среда: [условия], ключевые метрики: [LCP/INP/CLS/latency/build time]. Сначала проверь доступный способ измерения; сохрани сравнимые результаты в `.ecc/benchmarks` только если каталог и формат проекта это предусматривают. Укажи ограничения замера.
```

### 3. Подробный запрос
```text
/ecc-benchmark Измерь [страница/endpoint/сборка] и оцени [целевой порог/изменение]. 1) Зафиксируй среду, версию приложения, входные данные и методику; не сравнивай несопоставимые прогоны. 2) Сними применимые метрики: для браузера LCP, INP, CLS и вес страницы; для API — перцентили задержки; для разработки — время сборки/тестового цикла. 3) При сравнении получи baseline и post-change тем же способом и объясни шум/ограничения. 4) Не делай деплой и не выполняй внешних действий. Сохраняй JSON в `.ecc/benchmarks` лишь по существующей схеме проекта. Результат: условия, таблица измерений, дельты и вывод относительно цели.
```
