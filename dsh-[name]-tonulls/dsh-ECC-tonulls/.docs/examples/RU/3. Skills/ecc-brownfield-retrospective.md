# `/ecc-brownfield-retrospective`

Ретроспективно применяет инженерный процесс ECC к существующему фрагменту проекта: изучает текущее состояние, восстанавливает решения, строит реестр пробелов по четырём осям (мышление, практика разработки, недостающие функции, выбор технологий), затем при отдельном поручении ведёт исправления через plan–TDD–review.

## Короткий запрос

```text
/ecc-brownfield-retrospective Оцени унаследованный модуль платежей: восстанови причины текущей архитектуры и составь приоритетный реестр пробелов, пока без правок.
```

## Шаблон

```text
/ecc-brownfield-retrospective Проведи ретроспективу участка [путь/подсистема] в проекте [репозиторий]. Контекст наследования: [что известно]. Сначала только аудит: зафиксируй доказательства и неизвестные по четырём осям — инженерное мышление, практика кода, недостающие возможности, выбор технологий. Исправления не начинай без отдельного согласия.
```

## Поэтапный запрос

```text
/ecc-brownfield-retrospective Разбери [участок проекта] после [переход команды/длительной разработки/внедрения ECC].
1. Зафиксируй границы аудита и исследуй текущее состояние, историю/документацию и доступные решения; не выдавай предположения о прошлом за подтверждённые факты.
2. Составь реестр пробелов по четырём осям: качество постановки/мышления, практика реализации, недостающие продуктовые возможности, обоснованность технологий.
3. Для каждого пункта укажи свидетельства (пути/артефакты), последствия, серьёзность и уверенность; обозначь, что проверить у команды.
4. Сначала представь выводы и предложенный порядок. К исправлениям переходи только после моего явного одобрения конкретного объёма; тогда планируй и выполняй малые шаги через plan–TDD–review.
5. Не устанавливай зависимости, не используй сеть и не выполняй деплой без отдельного согласия.

Вывод: краткое состояние участка, таблица пробелов с доказательствами и приоритетом, вопросы и безопасный план действий. Если запрошен аудит, никаких изменений кода.
```
