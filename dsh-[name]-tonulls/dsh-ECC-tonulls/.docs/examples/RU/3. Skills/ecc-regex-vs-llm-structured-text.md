# `/ecc-regex-vs-llm-structured-text`

Помогает спроектировать недорогой гибридный разбор структурированного текста: регулярные выражения извлекают типовые данные, оценка уверенности выделяет неоднозначные случаи, а LLM предлагается только как валидатор исключений.

## Простой запрос

```text
/ecc-regex-vs-llm-structured-text Спроектируй разбор счетов: regex для типовых полей, проверка уверенности и обработка неоднозначных случаев.
```

## Шаблонный запрос

```text
/ecc-regex-vs-llm-structured-text
Тип документов: [счета/анкеты/чеки/таблицы]
Нужные поля: [перечень]
Примеры входа: [обезличенные фрагменты]
Ограничения по цене и точности: [значения]
Предложи regex-first конвейер, оценку уверенности и критерии передачи отдельных случаев LLM. Не используй реальные персональные данные или секреты.
```

## Подробный запрос

```text
/ecc-regex-vs-llm-structured-text
Разработай план извлечения данных из [тип документов] для полей [перечень]. Работай по этапам:
1. Зафиксируй формат входов, варианты представления и критерии корректности.
2. Раздели поля на извлекаемые регулярными выражениями и требующие контекстной интерпретации.
3. Опиши regex-first извлечение и нормализацию без предположений, не подтверждённых примерами.
4. Предложи оценку уверенности, пороги ручной проверки и передачу только пограничных случаев LLM.
5. Определи тестовые примеры, метрики точности/полноты, стоимости и правила обработки ошибок.
Ограничения: не отправляй данные в сеть или сторонние сервисы; не используй настоящие персональные данные; ничего не устанавливай и не меняй в проекте. Сначала выдай проект решения, затем укажи допущения, риски и план проверки.
```
