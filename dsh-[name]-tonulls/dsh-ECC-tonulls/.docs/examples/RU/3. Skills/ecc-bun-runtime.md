# `/ecc-bun-runtime`

Помогает оценить Bun как runtime, package manager, bundler и test runner, выбрать между Bun и Node, спланировать миграцию и учесть поддержку Vercel. Подходит для инженерных решений, а не для предположения, что все инструменты совместимы автоматически.

## Короткий запрос

```text
/ecc-bun-runtime Сравни Bun и Node для нашего TypeScript CLI: учти runtime API, тесты и совместимость зависимостей.
```

## Шаблон

```text
/ecc-bun-runtime Оцени [Bun/переход с Node] для проекта [тип приложения, версии и ключевые зависимости]. Рассмотри нужные роли Bun: [runtime / менеджер пакетов / bundler / test runner], фактическую совместимость, Vercel [если применимо] и стоимость миграции. Не запускай установку и не меняй lockfile.
```

## Поэтапный запрос

```text
/ecc-bun-runtime Подготовь решение о применении Bun в [проект/сценарий]. Текущая среда: [Node/Bun версии, ОС/CI, framework, hosting]. Критерии: [скорость, совместимость, воспроизводимость, поддержка команды].
1. Раздели роли: выполнение приложения, установка пакетов, сборка и тесты; для каждой проверь требования и ограничения отдельно.
2. Сопоставь текущие версии и зависимости проекта с доступными свидетельствами совместимости. Не обобщай результаты для одной версии на все версии.
3. Если целевой хостинг Vercel, отдельно проверь его runtime/build ограничения для заданного способа запуска; не обещай поддержку без подтверждения.
4. Предложи постепенный план пробного перехода и критерии остановки/отката. Ничего не устанавливай, не обращайся к сети и не изменяй конфигурацию без согласия.

Результат: сравнительная таблица по четырём ролям, риски и неизвестные, рекомендация с условиями и минимальный план валидации. Не выдумывай результаты бенчмарков или совместимости.
```
