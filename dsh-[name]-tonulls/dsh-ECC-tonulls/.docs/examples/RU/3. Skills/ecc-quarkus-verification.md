# `/ecc-quarkus-verification`

**Назначение:** Цикл проверки проектов Quarkus: сборка, статический анализ (Checkstyle, PMD, SpotBugs), тесты и покрытие JaCoCo, проверки безопасности зависимостей и контейнеров по OWASP, нативная компиляция GraalVM, health checks и проверка конфигурации. Используйте перед PR, после крупного рефакторинга или обновления зависимостей и перед развёртыванием.

## Короткий промт

```text
/ecc-quarkus-verification Составь подтверждённый конфигурацией план проверки Quarkus PR; команды пока не запускай.
```

## Шаблонный промт

```text
/ecc-quarkus-verification
Контекст: [ветка/PR, конфиги сборки и тестов, локальные инструменты и ограничения окружения].
Задача: проверить готовность Quarkus-изменения к PR/release для [целевой компонент/результат].
Фокус: build, static analysis, tests/coverage, security scans, native build, health/config checks и побочные эффекты каждой проверки.
Ограничения: Только анализ: файлы и данные не меняй, внешние/разрушающие проверки не запускай.
Формат: [краткий итог, доказательства/обоснования, риски и следующий шаг].
```

## Подробный промт

```text
/ecc-quarkus-verification
Выполни задачу «проверить готовность Quarkus-изменения к PR/release» для [целевая система/сценарий].
1. Уточни цель, scope, исходные сведения и критерии результата; перечисли недостающий контекст.
2. Изучи только относящиеся к запросу материалы и проверь: build, static analysis, tests/coverage, security scans, native build, health/config checks и побочные эффекты каждой проверки.
3. Сформулируй находки или варианты с фактами, рисками, критериями проверки и неразрешёнными вопросами; ничего не применяй.
4. Проверь выводы по заданным критериям, укажи доказательства, допущения и непроверенное.

Ограничения: Только анализ: файлы и данные не меняй, внешние/разрушающие проверки не запускай.
Оформи результат так: [ожидаемый формат]. Не придумывай факты; перед любым непредусмотренным побочным действием остановись и запроси согласие.
```
