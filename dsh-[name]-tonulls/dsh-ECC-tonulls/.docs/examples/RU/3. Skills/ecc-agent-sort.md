# `/ecc-agent-sort`

Составляет для конкретного репозитория обоснованный план установки ECC: распределяет skills, commands, rules, hooks и extras между наборами DAILY и LIBRARY после анализа потребностей проекта. Это планирование состава, а не автоматическая установка.

## Примеры промтов

### 1. Короткий запрос
```text
/ecc-agent-sort Проанализируй этот репозиторий и предложи, какие ECC skills и команды нужны ежедневно, а какие оставить в библиотеке. Ничего не устанавливай.
```

### 2. Шаблонный запрос
```text
/ecc-agent-sort Подготовь план состава ECC для [репозиторий/тип проекта]. Учитывай [языки, фреймворки, типичные задачи, ограничения команды]. Рассмотри skills, commands, rules, hooks и extras; для каждого предложи DAILY или LIBRARY с доказательством из репозитория. Это только рекомендация — файлы не менять.
```

### 3. Подробный запрос
```text
/ecc-agent-sort Составь доказательный план сокращения ECC для [репозиторий]. 1) Изучи структуру, manifest/config и реально используемые технологии; не делай выводов только по именам файлов. 2) Проведи отдельные repo-aware проходы по skills, commands, rules, hooks и extras и сведи пересечения. 3) Для каждой позиции укажи DAILY (часто нужна) или LIBRARY (редкая/специализированная), привязав решение к найденным признакам; сомнительное отметь отдельно. 4) Не удаляй, не перемещай и не устанавливай компоненты. Результат: краткий профиль проекта, таблица «компонент — корзина — обоснование», список потенциальных пробелов/дубликатов и план внедрения только после отдельного подтверждения.
```
