# ecc-nodejs-keccak256

**Команда:** `/ecc-nodejs-keccak256`

**Назначение:** предотвращение ошибок Ethereum-хеширования в JavaScript/TypeScript: `sha3-256` Node.js — это NIST SHA-3, а не Ethereum Keccak-256; различие критично для селекторов, подписей, storage slots и derivation адресов.

## Промты

### 1. Короткий запрос

> /ecc-nodejs-keccak256 Проверь, не использует ли этот код NIST SHA3 вместо Ethereum Keccak-256: [фрагмент]. Объясни последствия и корректный способ проверки.

### 2. Шаблон с контекстом

> /ecc-nodejs-keccak256 Среда: [Node.js/TS, версия]; библиотека хеширования: [название/версия]; входные байты и кодировка: [описание]; ожидаемый результат: [hex/значение]; фактический результат: [значение]. Определи, где возможна путаница SHA3-256 и Keccak-256. Проверь кодирование входа и формат вывода; не подменяй алгоритм и не выдумывай ожидаемые хеши.

### 3. Подробный запрос

> /ecc-nodejs-keccak256 Диагностируй неверный Ethereum-хеш для [selector/signature/storage slot/address derivation] в приложенном JavaScript/TypeScript. 1) Проследи формирование точных входных байтов: текстовая кодировка, префиксы, padding и сериализация. 2) Установи фактический алгоритм API — отдельно проверь, не является ли `sha3-256` NIST SHA-3 вместо Keccak-256. 3) Проверь применимость результата к указанному Ethereum use case и правила преобразования результата в selector/slot/address; не смешивай Keccak с правилами EIP-55 или ABI без оснований. 4) Предложи библиотечный вызов и независимый контрольный тест с известным вектором, но не придумывай вектор. Не меняй файлы и не устанавливай зависимости. Формат: найденная причина, цепочка байтов → алгоритм → результат, минимальная рекомендация и тест-критерии.
