# `/ecc-rails-patterns`

**Назначение:** Практики Ruby on Rails для приложений Rails 7.1+ и 8.x: структура каталогов, тонкие контроллеры с сервисными объектами, формы и запросы как отдельные объекты, идиоматичный ActiveRecord, фоновые задачи, ViewComponent, Hotwire и стек Solid в Rails 8. Используйте при разработке или проверке приложений, контроллеров, моделей, сервисов, задач и представлений Rails.

## Короткий промт

```text
/ecc-rails-patterns Проверь Rails-контроллер и модель на N+1, смешение обязанностей и несогласованность с паттернами проекта.
```

## Шаблонный промт

```text
/ecc-rails-patterns
Контекст: [путь к Rails-модулю, версия, сценарий и принятые паттерны репозитория].
Задача: проверить архитектуру или реализацию Rails-приложения для [целевой компонент/результат].
Фокус: skinny controllers, service/query/form objects, ActiveRecord, jobs, ViewComponent/Hotwire и Rails Solid stack по применимости.
Ограничения: Только анализ: файлы и данные не меняй, внешние/разрушающие проверки не запускай.
Формат: [краткий итог, доказательства/обоснования, риски и следующий шаг].
```

## Подробный промт

```text
/ecc-rails-patterns
Выполни задачу «проверить архитектуру или реализацию Rails-приложения» для [целевая система/сценарий].
1. Уточни цель, scope, исходные сведения и критерии результата; перечисли недостающий контекст.
2. Изучи только относящиеся к запросу материалы и проверь: skinny controllers, service/query/form objects, ActiveRecord, jobs, ViewComponent/Hotwire и Rails Solid stack по применимости.
3. Сформулируй находки или варианты с фактами, рисками, критериями проверки и неразрешёнными вопросами; ничего не применяй.
4. Проверь выводы по заданным критериям, укажи доказательства, допущения и непроверенное.

Ограничения: Только анализ: файлы и данные не меняй, внешние/разрушающие проверки не запускай.
Оформи результат так: [ожидаемый формат]. Не придумывай факты; перед любым непредусмотренным побочным действием остановись и запроси согласие.
```
