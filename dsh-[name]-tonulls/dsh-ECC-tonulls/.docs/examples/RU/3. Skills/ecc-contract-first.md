# `/ecc-contract-first`

Координирует изменения между потребителем и поставщиком через единый машиночитаемый контракт (OpenAPI, AsyncAPI, Protobuf или JSON Schema), генерацию типов и проверку интеграции.

## Простой запрос

```text
/ecc-contract-first Помоги согласовать контракт нового REST-эндпоинта между фронтендом и сервисом заказов.
```

## Шаблонный запрос

```text
/ecc-contract-first
Поставщик: [сервис и стек]
Потребители: [клиенты]
Формат контракта: [OpenAPI/AsyncAPI/Protobuf/JSON Schema]
Изменение: [поля и поведение]
Ограничения совместимости: [описание]
Предложи единственный источник правды и проверки, исключающие расхождение mock и production.
```

## Подробный запрос

```text
/ecc-contract-first
Для изменения [API/событие] между [поставщик] и [потребители] предложи contract-first план. Сначала проверь текущие интерфейсы и ограничения совместимости; выбери уместный формат контракта из OpenAPI, AsyncAPI, Protobuf или JSON Schema; зафиксируй обязательность, ошибки, версии и эволюцию полей; опиши генерацию типов и проверки интеграции, чтобы mock соответствовал реальному формату. Раздели работу на поставщика и потребителей с критериями готовности. Не меняй файлы и не добавляй инструменты/зависимости без подтверждения. Итог: контрактный набросок, этапы, проверки, риски и неизвестные.
```
