# ecc-living-docs-governance

**Команда:** `/ecc-living-docs-governance`

**Назначение:** Предотвращение устаревания документации в долгоживущем проекте: назначение существующим документам ролей «конституция», «карта», «статус», «история» и связывание активной агентской среды с каноническими источниками. Предпочитает текущую структуру репозитория новым корневым файлам.

## Промты

### 1. Короткий запрос

> /ecc-living-docs-governance Проанализируй, какие документы этого проекта расходятся с кодом и какие уже являются каноническими источниками для контекста агента. Пока ничего не меняй.

### 2. Шаблон с заполнителями

> /ecc-living-docs-governance Проект [путь/репозиторий], проблема дрейфа: [пример/область], активная среда агента: [инструкции/файлы]. Проведи инвентаризацию существующей документации и предложи роли «правила», «карта», «текущее состояние», «история» только там, где это оправдано. Сначала покажи источники, пробелы и план; сохраняй текущую структуру и не создавай новые корневые документы без необходимости.

### 3. Подробный поэтапный запрос

> /ecc-living-docs-governance Спроектируй governance живой документации для долгоживущего репозитория [путь]. 1) Инвентаризируй существующие инструкции, карты, планы, заметки о состоянии и историю; сопоставь их назначение и признаки актуальности с кодом. 2) Определи канонический источник для каждого типа контекста, зафиксируй дублирование и противоречия. 3) Предложи минимальные изменения, используя существующую структуру; для агентского harness укажи, как направить его к каноническим файлам. 4) Отдельно рассмотрите удалённые/устаревшие элементы и защиту от их случайного воссоздания, если такая проблема подтверждена. Формат: карта документов, реестр расхождений с доказательствами, решение по ролям и ограниченный план внедрения. Не выдумывай факты о процессе; до согласия ничего не редактируй, не меняй код, не устанавливай ПО и не обращайся к сети.
