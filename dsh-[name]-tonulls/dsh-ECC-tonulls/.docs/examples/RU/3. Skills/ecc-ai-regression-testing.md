# `/ecc-ai-regression-testing`

Стратегии регрессионного тестирования при AI-разработке: изолированные API-проверки без базы данных, автоматизированный поиск дефектов и защита от слепых зон, когда одну и ту же правку пишет и проверяет одна модель.

## Примеры промтов

### 1. Короткий запрос
```text
/ecc-ai-regression-testing Предложи регрессионные проверки для этой AI-сгенерированной правки: [описание]. Отметь, какие ошибки автор-модель могла не заметить.
```

### 2. Шаблонный запрос
```text
/ecc-ai-regression-testing Для изменения [функция/API] в [проект/стек] составь план регрессионного покрытия. Условия: [можно ли обращаться к БД/внешним сервисам]. Укажи сценарии, ожидаемые результаты и способ проверить их изолированно; отдельно добавь независимые проверки против слепых зон модели.
```

### 3. Подробный запрос
```text
/ecc-ai-regression-testing Разработай проверяемый план регрессии для изменения [путь/описание] в [стек]. 1) Выведи поведение до и после правки из имеющихся требований и кода. 2) Составь позитивные, негативные и граничные сценарии, включая вероятные ошибки AI-реализации. 3) Для API предложи sandbox-проверки без зависимости от базы данных, если это применимо. 4) Не изменяй файлы и не устанавливай зависимости. Результат: таблица «сценарий — вход — ожидаемый результат — уровень изоляции», затем пробелы покрытия и приоритеты.
```
