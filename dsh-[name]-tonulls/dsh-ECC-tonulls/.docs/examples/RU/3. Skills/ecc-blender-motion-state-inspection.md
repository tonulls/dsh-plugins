# `/ecc-blender-motion-state-inspection`

Помогает исследовать в Blender персонажа, риг, позу, ретаргетинг анимации, контакт с поверхностью, направление взгляда/движения и соответствие модели движению. Для таких случаев одного скриншота часто недостаточно: запрос должен задавать, какие состояния и признаки сопоставить.

## Короткий запрос

```text
/ecc-blender-motion-state-inspection Проверь, почему персонаж проскальзывает при ходьбе: сопоставь позу стоп, контакт с землёй и движение рига по кадрам.
```

## Шаблон

```text
/ecc-blender-motion-state-inspection Исследуй [персонаж/сцена/анимация] в [файл или коллекция]. Подозрение: [ошибка позы/ретаргетинга/контакта/ориентации]. Проверь интервал кадров [от—до], исходный риг [описание] и целевой [описание]. Нужны наблюдаемые причины и точные кадры/объекты, не догадки по одному изображению.
```

## Поэтапный запрос

```text
/ecc-blender-motion-state-inspection Диагностируй [симптом] в сцене [файл/сцена], диапазон [кадры], персонаж [объект], риг [объект].
1. Уточни доступные данные сцены и способ проверки; если нет доступа к Blender/состояниям кадров, явно перечисли недостающие сведения.
2. Проследи позы и трансформации рига по ключевым кадрам [указать]; отдельно проверь root motion и ориентацию персонажа.
3. Для ретаргетинга сравни соответствие костей/осей и масштаба исходного и целевого ригов, если обе стороны доступны.
4. Проверь ground contact по движению стоп относительно поверхности и соседних кадров; отличай контакт от визуального совпадения в одном кадре.
5. Сформулируй проверяемую причину и минимальные варианты исправления; ничего не меняй в сцене без явного поручения.

Формат: наблюдения с кадрами и именами объектов; гипотезы отдельно от подтверждённых фактов; вероятная причина; следующий проверочный шаг. Не утверждай, что проверил недоступное состояние.
```
