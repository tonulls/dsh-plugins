# `/ecc-content-hash-cache-pattern`

Предлагает паттерн кэширования дорогой обработки файлов по SHA-256 содержимого, независимо от пути, с автоматической инвалидацией и отделением сервисного слоя.

## Простой запрос

```text
/ecc-content-hash-cache-pattern Как кэшировать результат разбора файла так, чтобы изменение содержимого автоматически сбрасывало кэш?
```

## Шаблонный запрос

```text
/ecc-content-hash-cache-pattern
Стек: [язык и хранилище]
Обработка: [что дорого вычислять]
Объём/частота: [оценка]
Требования к сроку жизни и конкуренции: [условия]
Предложи схему SHA-256-кэша и границы сервисного слоя, учитывая текущий код: [фрагменты].
```

## Подробный запрос

```text
/ecc-content-hash-cache-pattern
Спроектируй для [стек] кэш результатов операции [обработка]. Требования: одинаковое содержимое по разным путям должно переиспользовать результат; изменение байтов должно инвалидировать запись; поведение при коллизии/ошибке/параллельной обработке должно быть определено; кэш не должен менять бизнес-результат. Поэтапно опиши ключ и сериализацию, разделение вычисления и хранилища, политику очистки и безопасное поведение при сбое. Приведи пример API и тесты на повторное использование, изменение содержимого, разные пути и конкурентные запросы. Сначала только анализ и предложение — файлы не меняй, зависимости не устанавливай. Отчёт: схема, компромиссы, тестовый план и необходимые уточнения.
```
