# Critique a UI

Choose a representative user and a concrete task. Walk through only the affected surface and record where the task stalls. Look for competing actions, unclear labels, missing feedback, unnecessary memory demands and information that appears before it is needed. Check the relevant keyboard, narrow-screen, error and reduced-motion states.

For each finding record the screen or component, observed evidence, user impact and a specific improvement. Keep unverified concerns separate from observations. Rank findings by their effect on task completion and accessibility. Do not assign scores when there is insufficient evidence.

At each decision, identify what the user must remember from a previous screen. Check whether
the interface keeps the relevant choice, status, or comparison visible at the point of action.
When the task itself is complex, preserve the information needed to decide and remove unrelated
choices or repeated explanation. Test whether someone can resume the task after an interruption.
